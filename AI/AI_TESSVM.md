# tessvm — PixiJS 로 도는 Tess 실행기

`packages/tessvm` 은 Tess 작품을 **엔트리와 같은 규칙으로, 훨씬 빠르게** 돌리는 실행기입니다.
엔트리 실행기(entryjs)를 불러다 쓰지 않고, 블록을 자바스크립트로 컴파일해서 PixiJS 위에서
직접 돌립니다.

```bash
pnpm tessvm run   examples/all_blocks.tess     # 컴파일해서 브라우저로 실행
pnpm tessvm run   game.ent                     # ent → Tess 로 되돌린 뒤 실행
pnpm tessvm bench game.ent                     # 화면 없이 돌려 속도 측정
pnpm tessvm emit  game.ent                     # JIT 가 만든 자바스크립트 출력
pnpm tessvm check game.ent                     # 아직 못 도는 블록 보고
```

## 1. 무엇을 실행하는가 — Tess 실행기이지 엔트리 실행기가 아니다

tessvm 이 받는 것은 **언제나 Tess** 입니다.

```
main.tess ──@tess/compiler──▶ 엔트리 작품(project.json) ──JIT──▶ JS ──▶ PixiJS
game.ent  ──@tess/decompiler──▶ main.tess ──▲ (같은 길)
```

`.ent` 는 먼저 `@tess/decompiler` 로 Tess 소스로 되돌린 뒤(`--keep <폴더>` 로 그 소스를
남길 수 있습니다) 같은 길을 지나갑니다. 그래서 "엔트리 작품이 도는 것"은 결과이고,
tessvm 이 실제로 아는 것은 Tess 뿐입니다.

중간에 엔트리 작품 형식을 지나가는 이유는 두 가지입니다.

1. Tess → 엔트리 블록 대응은 이미 `@tess/compiler` 가 실제 작품과 대조해 가며 맞춰 둔
   것입니다(블록 이름·파라미터 순서·`scale_x` 같은 없는 블록 만들어 내기·거듭제곱 펼치기).
   이것을 또 만들면 두 벌이 서로 어긋납니다.
2. **프레임 경계가 블록 단위로 정의됩니다.** "엔트리와 똑같이 실행" 은 결국 "어느 블록에서
   프레임을 넘기는가" 이므로, 블록이 실행 단위로 남아 있어야 그 규칙을 그대로 옮길 수 있습니다.

| 파일                              | 역할                                                      |
| --------------------------------- | --------------------------------------------------------- |
| `src/node/cli.ts`                 | `tessvm` 명령 (`run`·`bench`·`emit`·`check`)              |

| `src/runtime/model.ts`            | 오브젝트·복제본·변수의 상태와 그 변경 규칙                |

## 2. JIT — 블록을 해석하지 않고 자바스크립트로 만든다

엔트리는 매 틱마다 블록 트리를 걸어 다니며 `Entry.Scope` 를 만들고, `paramsKeyMap` 으로
파라미터 자리를 찾고, `getValue` 로 중첩 블록을 다시 평가합니다. tessvm 은 작품을 열 때 딱
한 번 그 트리를 훑어 **제너레이터 함수의 소스**를 만들고 `new Function` 으로 컴파일합니다.

```js
// 원본: 10번 반복 { 이동 방향으로 10 만큼 움직이기; 점수 += 1 }
function* (e, th) {
  { let i0 = Math.floor(10);
  while (i0 !== 0 && !(i0 < 0)) { i0--;
    O.moveDirection(e, 10);
    O.changeVariable(e, 3, "1");
    yield 0;
  } }
}
```

- **리터럴은 접어 둡니다.** `n("10")` 이 아니라 `10` 이 박힙니다.
- **이름은 인덱스로 풀어 둡니다.** 변수·오브젝트·함수·표는 컴파일 시점에 배열 번호가 됩니다.
- **형 변환을 생략합니다.** 이미 숫자를 돌려주는 자리에는 `n(...)` 을 씌우지 않습니다
  (`Value.kind`).
- **모르는 블록은 주석 한 줄**로 남고 실행을 멈추지 않습니다. `tessvm check` 가 그 목록을
  보고합니다.

### 프레임 경계 — `yield` 가 곧 엔트리의 `BREAK`

엔트리의 `Entry.Executor.execute` 는 블록의 반환값으로 프레임을 넘길지 정합니다. 그중
실제로 관측되는 규칙만 남기면 이렇습니다.

| 엔트리                                                       | tessvm                                  |
| ------------------------------------------------------------ | --------------------------------------- |
| 반복 블록이 `getStatement` → 속이 끝나면 `isLooped` 가 달라 BREAK | `while (…) { …; yield 0; }`             |
| `_if` 는 `isCondition` 만 세우고 BREAK 하지 않음             | 그냥 `if (…) { … }` — 프레임을 넘기지 않음 |
| `wait_second` 가 `timeFlag` 가 0 이 될 때까지 `script` 반환   | `yield* O.waitSecond(…)`                |
| `stop_repeat` → `breakLoop()` 는 PASS (같은 프레임에 이어감)  | `break;`                                |
| `continue_repeat` → `continueLoop()` 는 BREAK                 | `{ yield 0; continue; }`                |
| `func_<id>` 가 안 끝나면 BREAK, 다음 프레임에 이어서          | `yield* F[i](e, th, [인수…])`           |

**반복은 한 바퀴마다 정확히 한 프레임**이고, `10번 반복` 뒤의 문장은 **11번째 프레임**에
돕니다(마지막 바퀴 다음 프레임에 반복 조건을 확인하고 그 프레임에서 이어서 실행). 이
규칙 때문에 컴파일러가 거듭제곱을 반복문이 아니라 펼친 식으로 만드는 것이기도 합니다
(AI_README.md 참고).

값 함수가 중간에 프레임을 넘겨야 할 때도 `yield*` 가 그대로 표현식 자리에 들어갑니다 —
자바스크립트 제너레이터는 표현식 안의 `yield*` 를 허용하므로, 엔트리가 Promise 와
`valueMap` 캐시로 하던 일을 문법 하나로 대신합니다.

### 오브젝트 지역 변수와 복제본

엔트리에서 오브젝트 지역 변수는 **복제본마다 따로**입니다
(`variableContainer.getVariable(id, entity)` 가 `entity.isClone && variable.object_` 이면
`entity.variables` 에서 다시 찾습니다). tessvm 도 복제할 때 그 오브젝트의 지역 변수만
복사해서 `entity.localVars` 에 같은 인덱스로 담아 둡니다. 전역 변수는 배열 하나를 그대로
씁니다.

## 3. 값 — 엔트리의 산술은 2진수가 아니라 10진수다

엔트리의 `calc_basic` 은 **BigNumber** 로 계산합니다. 그래서 엔트리에서 `0.1 + 0.2` 는
`0.30000000000000004` 가 아니라 **`0.3`** 입니다. 이것을 무시하면 좌표·체력 계산이 조금씩
어긋나다가 비교식에서 갈라집니다.

BigNumber 를 그대로 쓰면 느리므로 `cast.ts` 는 같은 결과를 배정밀도만으로 냅니다.

- 양쪽이 정수면 그냥 계산합니다 — 이때 배정밀도 결과와 10진 결과는 항상 같습니다.
- 아니면 두 피연산자의 **소수 자릿수**로 결과를 되돌려 놓습니다
  (`Number(result.toFixed(p))`). 10진 결과가 가지는 자릿수가 `p` 이하이므로 이 반올림은
  정확히 그 값을 되찾습니다.
- 나누기는 BigNumber 가 20자리에서 끊으므로, 몫이 `1e-3` 보다 작을 때만 `toFixed(20)` 을
  거칩니다. 그보다 크면 배정밀도 나눗셈이 이미 같은 값입니다.

그 밖에 그대로 옮긴 규칙들:

| 자리                      | 규칙                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| 값 칸을 숫자로 읽기       | `parseFloat(v) \|\| 0` — `"12abc"` 는 12, `"abc"` 는 0            |
| 값 칸을 판단으로 읽기     | 숫자로 읽히면 그 진리값, 아니면 참 — `"0"`·`"0.00"` 만 거짓        |
| `같다`                    | 숫자로 읽히는 문자열은 숫자로 바꾼 뒤 **엄격 비교(`===`)**        |
| `같지 않다`               | 같은 변환 뒤 **느슨한 비교(`!=`)** — 엔트리의 비대칭을 그대로     |
| `+`                       | 양쪽이 숫자 꼴이 아니면 이어 붙이기                               |
| `그리고`·`또는`           | 두 쪽을 **모두 평가한 뒤** 결합 (엔트리는 단축 평가를 하지 않음)  |
| 나머지                    | 나누는 수의 부호를 따름 (`-1 mod 360 = 359`)                      |
| `변수 바꾸기`             | 결과를 `toFixed` 한 **문자열**로 저장 — 엔트리가 그렇게 합니다    |
| `사인`·`코사인`·`탄젠트`  | 30° 배수는 표에 든 정확한 값 (`Entry.preciseTrig`)                |

## 4. 충돌 — 같은 판정, 훨씬 적은 일

엔트리의 `~에 닿았는가?` 는 `ndgmr.checkPixelCollision` 으로 갑니다. 그 안에서 하는 일은

1. 두 스프라이트의 **월드 경계 상자**를 구해 겹치는 사각형을 찾고,
2. 그 사각형 크기의 **캔버스를 두 장 새로 만들어** 각 스프라이트를 world transform 그대로
   다시 그린 뒤,
3. `getImageData` 로 두 장의 알파를 읽어 **같은 자리에서 둘 다 51 을 넘는지**(임곗값 0.2)
   봅니다.

판정 한 번에 캔버스 두 장 + `drawImage` 두 번 + `getImageData` 두 번입니다. 총알 30개가
매 프레임 벽과 적을 확인하면 이것만으로 프레임이 무너집니다.

tessvm 은 **판정 결과는 그대로 두고 그리기만 없앱니다.**

- 모양마다 **알파 마스크**(픽셀당 1바이트)를 처음 한 번만 만들어 둡니다
  (`MaskStore`, 그 모양이 실제로 충돌에 쓰일 때 만듭니다).
- 겹치는 사각형은 엔트리와 **같은 640×360 무대 픽셀 공간**에서 같은 식으로 구합니다
  (무대 컨테이너가 `(320,180)`, 배율 `4/3` — `Entry.stage.initStage`). 그래서 판정의 해상도가
  화면 해상도와 무관하게 엔트리와 같습니다.
- 그 사각형을 한 픽셀씩 훑되, 픽셀마다 행렬을 곱하지 않고 **역변환의 증분만 더합니다**
  (한 픽셀에 덧셈 네 번). 두 마스크를 찾아보고 하나라도 맞으면 곧바로 끝냅니다.
- 마스크마다 **불투명한 부분의 경계 상자**를 재 두어 그 밖은 아예 보지 않습니다.
- 같은 프레임 안에서 같은 짝을 다시 물어보면 **캐시**로 답합니다. 키에는 두 오브젝트의
  `version`(좌표·크기·회전·모양이 바뀔 때마다 오르는 번호)이 들어가므로, 움직인 뒤에는
  캐시가 저절로 무효가 됩니다.

벽은 엔트리와 같습니다 — 무대 밖 30단위 띠 네 개(`bound.png` 는 알파가 없는 회색조 PNG 라
언제나 불투명)이고, `bounce_wall` 은 임곗값 0(알파 > 0), `reach_something` 은 0.2 입니다.
`bounce_wall` 의 "한 번 튕긴 벽은 떨어질 때까지 다시 튕기지 않는다" 상태 기계
(`entity.collision`)도 그대로 옮겼습니다.

마우스 판정은 엔트리의 PIXI 경로(`containsPoint` → `_pixelHasAlpha`, 알파 > 1)를 따릅니다.

**남는 차이 하나.** 엔트리는 캔버스에 다시 그리므로 크기를 줄인 스프라이트의 알파가
보간되어 옅어집니다. tessvm 은 마스크를 최근접으로 찾아봅니다. 크게 줄인 그림의 가장자리
한두 픽셀에서 판정이 갈릴 수 있고, 그 밖의 경우는 같습니다.

## 5. 렌더러 — 좌표는 엔트리 그대로, 화질만 올린다

무대 컨테이너를 엔트리와 똑같이 `(320,180)` 에 놓고 `4/3` 배로 키웁니다. 화질은 그 위에서
**`renderer.resolution` 만** 올립니다 — 캔버스 버퍼만 커지고 무대 좌표계는 640×360 으로
남으므로, 엔트리 코드에 픽셀 값으로 박혀 있는 위치들이 그대로 맞습니다.

```
resolution = (화면에 그려질 CSS 폭 / 640) × devicePixelRatio × 화질배수
```

즉 기본값(1×)에서 이미 **화면 픽셀 1:1** 입니다. 2×·4× 는 그 위에 초과 표본화를 얹습니다.

**상태 반영은 프레임 끝에 한 번만 합니다.** VM 이 좌표를 바꿀 때 하는 일은 `entity.dirty`
를 세우는 것뿐이고, `flush()` 가 그 프레임에 실제로 달라진 오브젝트만 PIXI 에 옮깁니다.
엔트리는 `setX` 한 번에 PIXI 속성을 바로 건드리고 `updateDialog`·`updateCoordinateView`
까지 부르므로, 한 프레임에 좌표를 여러 번 바꾸는 코드에서 차이가 큽니다.

효과(밝기·색깔·투명도)는 엔트리가 만드는 것과 **같은 색 행렬**을 씁니다. 밝기는
`값/255` 를 오프셋 열에 넣고(`GEHelper.colorFilter.brightness`, pixi 의 `_loadMatrix` 는
`multiply=false` 일 때 정규화를 하지 않으므로 이 나눗셈이 곧 정규화입니다), 색깔은
`hsv` 값에 따라 채널을 돌리는 세 가지 행렬 중 하나입니다.

말풍선은 `Entry.Dialog` 의 값을 그대로 씁니다 — 15px 글자, 여백 10, 흰 바탕에 `#4f80ff`
2px 테두리, 꼬리는 오브젝트 경계 상자를 기준으로 네 방향(`nw`·`ne`·`sw`·`se`) 중 하나.

캔버스에 그릴 이유가 없는 것은 HTML 로 둡니다. **물어보기 입력창**이 그렇습니다 —
엔트리는 `CanvasInput` 으로 캔버스에 직접 그리기 때문에 해상도를 올리면 크기가 어긋나
`scaleInputFieldToBuffer` 같은 보정이 필요했지만(AI_README.md), HTML `<input>` 은 해상도와
무관하게 선명하고 모바일 키보드도 그대로 뜹니다.

## 6. 번들 단계가 없다

브라우저 쪽 코드도 `.ts` 그대로 두고, 서버가 내보낼 때 `stripTypeScriptTypes` 로 **타입만
지웁니다**. 타입은 공백으로 바뀌므로 줄과 열이 저장소와 같고, 개발자 도구에서 본 위치가
곧 파일의 위치입니다. `pixi.js` 는 임포트 맵으로 잇습니다.

```html
<script type="importmap">{"imports": {"pixi.js": "/vm/pixi.mjs"}}</script>
<script type="module">import { boot } from '/vm/web/boot.ts';</script>
```

이 때문에 브라우저용 파일에는 **지울 수 있는 문법만** 쓸 수 있습니다(`erasableSyntaxOnly`
— `enum`·`namespace`·생성자 매개변수 프로퍼티 금지). 저장소 전체가 이미 그 규칙이라
새로 지킬 것은 없습니다.

타입 검사는 두 벌입니다. 노드 쪽은 루트 `tsconfig.json`, 브라우저 쪽은
`packages/tessvm/tsconfig.browser.json`(`lib: dom`). 그래서 **DOM 타입이 노드 쪽으로
새지 않도록** 캔버스가 필요한 부분만 따로 뒀습니다 — `collision/mask.ts` 는 순수한 자료
구조이고 `collision/mask-image.ts` 만 캔버스를 씁니다. VM 은 `MaskStore` 에 "키를 주면
마스크를 돌려주는 함수" 를 받으므로, 브라우저에서는 렌더러가 그림에서 만들고 테스트에서는
직접 만들어 넣습니다.

## 7. 헤드리스 실행

렌더러와 소리를 `null` 로 두면 VM 만 돕니다. `tessvm bench` 와 테스트가 이 모드를 씁니다.

```ts
const vm = new Vm({ renderer: null, audio: null });
vm.load(project);
vm.start();
for (let i = 0; i < 600; i++) vm.tick();   // 10초치
```

실측(이 저장소의 예제, 노드 24, 화면 없음):

| 작품                   | 오브젝트 | 컴파일  | 틱당      |
| ---------------------- | -------- | ------- | --------- |
| `boss.ent`             | 139      | ~25 ms  | 0.004 ms  |
| `deltarune.ent`        | 136      | ~110 ms | 0.007 ms  |
| `witch.ent`            | 559      | ~75 ms  | 0.004 ms  |

브라우저에서 `deltarune.ent` 를 **그리기까지 포함해** 재면 프레임당 0.18 ms 정도입니다
(60fps 예산 16.7 ms 의 1%). 컴파일 시간은 작품을 열 때 한 번만 듭니다.

## 8. 지금 하지 못하는 것

`tessvm check <파일>` 이 그 작품에서 못 도는 블록을 세어 줍니다. 종류로 나누면 이렇습니다.

- **확장 블록** — 날씨·축제·재난문자·국민행동요령(12종). playentry.org 의 서버에서 자료를
  받아 오는 블록이라 그 API 없이는 값을 만들 수 없습니다. 지금은 값을 돌려주지 않고
  (`undefined`) 실행은 계속합니다.
- **인공지능·하드웨어 블록** — 오브젝트 인식·번역·음성 인식·모델 학습, 각종 로봇.
- **표 화면** — `표 보이기`·`차트 보이기`·`표 저장하기` 는 만들기 화면의 창을 여는
  블록이라 실행 중에는 아무 일도 하지 않습니다. 표를 **읽고 고치는** 블록(행·열 추가,
  값 읽기/쓰기, 합계·평균·표준편차·상관계수·조회)은 전부 동작합니다.
- **읽어주기(TTS)** 는 브라우저의 음성 합성으로 대신합니다. 엔트리는 playentry.org 가 만든
  mp3 를 받아 재생하므로 목소리가 다릅니다. 대신 인터넷 없이 동작합니다.
- **`오브젝트 순서 바꾸기`** 는 오브젝트 단위로만 옮깁니다. 엔트리는 복제본 하나를 따로
  옮길 수 있는데, tessvm 은 한 오브젝트의 복제본을 한 층에 모아 두기 때문입니다.

## 9. 판단이 필요했던 지점

**`부스트 모드인가?` 는 기본이 거짓입니다.** tessvm 은 언제나 WebGL 로 그리지만, 이 블록이
돌려주는 값은 따로 정합니다. playentry.org 는 부스트를 끈 채로 작품을 재생하고, 부스트에서
깨지던 작품들이 이 블록으로 "부스트 모드를 꺼주세요" 를 띄우기 때문입니다(실제로
`deltarune.ent` 가 그렇습니다). 참을 돌려주게 하려면 `--boost` 를 씁니다.

**제너레이터를 돌고 있는 중에 닫지 않습니다.** `자신의 다른 코드 멈추기`·장면 넘기기는
자기 자신을 멈출 수 있는데, 실행 중인 제너레이터에 `.return()` 을 부르면
`Generator is already running` 으로 터집니다. `Thread.stop` 은 실행 중이면 `done` 만
세우고 돌아갑니다 — 그 프레임은 코드가 알아서 끝납니다.

**모르는 블록에서 멈추지 않습니다.** 확장 블록 하나 때문에 작품 전체가 안 도는 것보다,
그 블록만 건너뛰고 나머지를 보여 주는 쪽이 낫습니다. 대신 `check` 로 정확히 무엇이
빠졌는지 셀 수 있게 했습니다. (컴파일러의 '느슨한 실행' 과 같은 태도입니다.)

**틱은 고정 60Hz 누적기로 돕니다.** 엔트리는 `setInterval(1000/60 을 내림한 16ms)` 라
실제로는 초당 62.5번 돕니다. tessvm 은 `requestAnimationFrame` 으로 화면을 맞추되 틱은
정확히 초당 60번 돌리고, 한 프레임에 밀린 틱은 최대 4번까지만 따라잡습니다(그 이상 밀리면
따라잡느라 더 밀리는 악순환이 됩니다).

**`change_variable` 은 문자열을 저장합니다.** 엔트리가
`new BigNumber(a).plus(b).toNumber().toFixed(자릿수)` 를 그대로 넣기 때문입니다. 값을
숫자로 바꿔 담으면 `문자/숫자인가?` 판단과 이어 붙이기 결과가 달라집니다.
