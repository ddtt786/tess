# tessvm — PixiJS 로 도는 Tess 실행기

`packages/tessvm` 은 Tess 작품을 **엔트리와 같은 규칙으로, 훨씬 빠르게** 돌리는 실행기입니다.
엔트리 실행기(entryjs)를 불러다 쓰지 않고, 블록을 자바스크립트로 컴파일해서 PixiJS 위에서
직접 돌립니다.

```bash
pnpm tess   run   examples/all_blocks.tess     # tess run 이 기본으로 쓰는 실행기
pnpm tess   run   examples/all_blocks.tess --entry   # 엔트리 실행기로 바꾸기
pnpm tessvm run   examples/all_blocks.tess     # 컴파일해서 브라우저로 실행
pnpm tessvm run   game.ent                     # ent → Tess 로 되돌린 뒤 실행
pnpm tessvm run   game.ent --stage 960x540     # 무대를 넓혀서 실행
pnpm tessvm bench game.ent                     # 화면 없이 돌려 속도 측정
pnpm tessvm emit  game.ent                     # JIT 가 만든 자바스크립트 출력
pnpm tessvm check game.ent                     # 아직 못 도는 블록 보고
```

`tess run` 은 **tessvm 으로 띄웁니다**. 엔트리 실행기로 보고 싶으면 `--entry` 를 붙입니다
(같은 작품·같은 디버그 패널이고, 그 작품을 무엇이 돌리는가만 다릅니다).

## 1. 무엇을 실행하는가 — Tess 실행기이지 엔트리 실행기가 아니다

tessvm 이 받는 것은 **언제나 Tess** 입니다.

```
main.tess ──@tess/compiler──▶ 엔트리 작품(project.json) ──JIT──▶ JS ──▶ PixiJS
game.ent  ──@tess/decompiler──▶ main.tess ──▲ (같은 길)
```

`.ent` 는 먼저 `@tess/decompiler` 로 Tess 소스로 되돌린 뒤(`--keep <폴더>` 로 그 소스를
남길 수 있습니다) 같은 길을 지나갑니다. 그래서 "엔트리 작품이 도는 것"은 결과이고,
tessvm 이 실제로 아는 것은 Tess 뿐입니다.

중간에 엔트리 작품 형식을 지나가는 이유는 두 가지입니다.

1. Tess → 엔트리 블록 대응은 이미 `@tess/compiler` 가 실제 작품과 대조해 가며 맞춰 둔
   것입니다(블록 이름·파라미터 순서·`scale_x` 같은 없는 블록 만들어 내기·거듭제곱 펼치기).
   이것을 또 만들면 두 벌이 서로 어긋납니다.
2. **프레임 경계가 블록 단위로 정의됩니다.** "엔트리와 똑같이 실행" 은 결국 "어느 블록에서
   프레임을 넘기는가" 이므로, 블록이 실행 단위로 남아 있어야 그 규칙을 그대로 옮길 수 있습니다.

| 파일                              | 역할                                                      |

## 2. JIT — 블록을 해석하지 않고 자바스크립트로 만든다

엔트리는 매 틱마다 블록 트리를 걸어 다니며 `Entry.Scope` 를 만들고, `paramsKeyMap` 으로
파라미터 자리를 찾고, `getValue` 로 중첩 블록을 다시 평가합니다. tessvm 은 작품을 열 때 딱
한 번 그 트리를 훑어 **제너레이터 함수의 소스**를 만들고 `new Function` 으로 컴파일합니다.

```js
// 원본: 10번 반복 { 이동 방향으로 10 만큼 움직이기; 점수 += 1 }
function* (e, th) {
  { let i0 = Math.floor(10);
  while (i0 !== 0 && !(i0 < 0)) { i0--;
    O.moveDirection(e, 10);
    O.changeVariable(e, 3, "1");
    yield 0;
  } }
}
```

- **리터럴은 접어 둡니다.** `n("10")` 이 아니라 `10` 이 박힙니다.
- **이름은 인덱스로 풀어 둡니다.** 변수·오브젝트·함수·표는 컴파일 시점에 배열 번호가 됩니다.
- **형 변환을 생략합니다.** 이미 숫자를 돌려주는 자리에는 `n(...)` 을 씌우지 않습니다
  (`Value.kind`).
- **모르는 블록은 주석 한 줄**로 남고 실행을 멈추지 않습니다. `tessvm check` 가 그 목록을
  보고합니다.

### 프레임 경계 — `yield` 가 곧 엔트리의 `BREAK`

엔트리의 `Entry.Executor.execute` 는 블록의 반환값으로 프레임을 넘길지 정합니다. 그중
실제로 관측되는 규칙만 남기면 이렇습니다.

| 엔트리                                                       | tessvm                                  |
| ------------------------------------------------------------ | --------------------------------------- |
| 반복 블록이 `getStatement` → 속이 끝나면 `isLooped` 가 달라 BREAK | `while (…) { …; yield 0; }`             |
| `_if` 는 `isCondition` 만 세우고 BREAK 하지 않음             | 그냥 `if (…) { … }` — 프레임을 넘기지 않음 |
| `wait_second` 가 `timeFlag` 가 0 이 될 때까지 `script` 반환   | `yield* O.waitSecond(…)`                |
| `stop_repeat` → `breakLoop()` 는 PASS (같은 프레임에 이어감)  | `break;`                                |
| `continue_repeat` → `continueLoop()` 는 BREAK                 | `{ yield 0; continue; }`                |
| 판단 자리의 `not(continue_repeat)` — `continueLoop()` 이 반복 블록까지 스코프를 되감고, `wait_until_true` 가 돌려준 스코프는 어느 분기에도 안 걸려 그 프레임에 그대로 이어감 | `continue;` (프레임을 넘기지 않음) |
| `func_<id>` 가 안 끝나면 BREAK, 다음 프레임에 이어서          | `yield* F[i](e, th, [인수…])`           |

**반복은 한 바퀴마다 정확히 한 프레임**이고, `10번 반복` 뒤의 문장은 **11번째 프레임**에
돕니다(마지막 바퀴 다음 프레임에 반복 조건을 확인하고 그 프레임에서 이어서 실행). 이
규칙 때문에 컴파일러가 거듭제곱을 반복문이 아니라 펼친 식으로 만드는 것이기도 합니다
(AI_README.md 참고).

값 함수가 중간에 프레임을 넘겨야 할 때도 `yield*` 가 그대로 표현식 자리에 들어갑니다 —
자바스크립트 제너레이터는 표현식 안의 `yield*` 를 허용하므로, 엔트리가 Promise 와
`valueMap` 캐시로 하던 일을 문법 하나로 대신합니다.

### 오브젝트 지역 변수와 복제본

엔트리에서 오브젝트 지역 변수는 **복제본마다 따로**입니다
(`variableContainer.getVariable(id, entity)` 가 `entity.isClone && variable.object_` 이면
`entity.variables` 에서 다시 찾습니다). tessvm 도 복제할 때 그 오브젝트의 지역 변수만
복사해서 `entity.localVars` 에 같은 인덱스로 담아 둡니다. 전역 변수는 배열 하나를 그대로
씁니다.

### 스레드를 멈출 때는 표시만 하고, 배열에서 빼지 않는다

`Entry.Code.clearExecutorsByEntity` 는 실행기에 `end()` 만 걸어 두고 배열은 건드리지
않습니다. 실제로 빼는 것은 `tick` 이고, 거기서는 `executors.splice(i--, 1)` 로 자기 자리
번호를 같이 되돌립니다. tessvm 의 `stopThreadsOf` · `stopOtherThreads` 도 `done` 만
세우고, `Vm.tick` 이 다음 바퀴에 걸러 냅니다.

도는 중에 배열에서 빼면 뒤에 있던 스레드가 이미 지나온 자리로 당겨져 **그 프레임을
통째로 건너뜁니다.** 복제본 한 무리가 같은 프레임에 저마다 `del clone` 을 하면 한 프레임에
절반씩만 지워져서, 한꺼번에 사라져야 할 글자들이 하나씩 사라지는 것처럼 보입니다.

### 함수 인자는 칸 번호로 읽는다

엔트리는 호출 블록의 슬롯을 **순서 그대로** `executor.register.params` 에 싣고, 본체는
`register.params[paramMap[type]]` 로 선언 번호를 따라 읽습니다. 그래서 비어 있는 슬롯도
자리를 차지합니다. 빈 칸을 걸러내면 그 뒤 인자가 전부 한 칸씩 밀립니다.

```ts
const args = block.params.map((param) => this.raw(param));
```

### 함수 본문은 두 가지 모양으로 온다

`함수 정의하기`(`function_create`)는 **모자 블록**입니다. 그래서 작품이 들고 있는 본문은
정의 블록이 놓인 **스택의 나머지**이고, playentry 가 graphql 로 내주는 데이터도, 엔트리
실행기가 실제로 실행하는 것도 이 모양입니다.

```
content = [[ function_create, _if, _if, … ]]        ← 작품(playentry)의 모양
```

작품을 `.ent` 로 저장하면 **같은 본문이 정의 블록의 칸 안으로** 들어갑니다.

```
content = [[ function_create{ statements: [[ _if, _if, … ]] } ]]    ← .ent 의 모양
```

`statements` 만 읽으면 playentry 에서 불러온 작품은 **함수가 전부 빈 껍데기**가 됩니다.
블록은 하나도 빠지지 않았으므로 모르는 블록도, 오류도 나지 않습니다 — 부르는 자리는
그대로 있고 아무 일도 일어나지 않을 뿐입니다. 맵을 함수로 짓는 작품이라면 장면에
들어가도 아무것도 지어지지 않고, 물리도 함수 안에 있으면 같이 멎습니다.

`codegen` 의 `functionBody()` 가 둘 다 읽습니다 — 칸 안에 있으면 그것을, 없으면 스택의
나머지를. `@tess/decompiler` 와 디버그 패널도 같은 규칙으로 정규화합니다.

### 팔레트에서 내려간 블록도 읽는다

엔트리는 블록 정의를 지우지 않습니다. 팔레트에 없어진 뒤에도 정의가 남아 있어서, 옛
작품이 들고 있는 블록은 그대로 돕니다. `codegen` 이 모르는 값 블록은 `null` 이 되므로,
그런 블록 하나가 판단식을 통째로 거짓으로 만듭니다.

| 블록                    | 지금 쓰는 것                | 하는 일                                        |
| ----------------------- | --------------------------- | ---------------------------------------------- |
| `boolean_and`           | `boolean_and_or` 의 `AND`   | 양쪽을 모두 읽고 `&&` — 짧은 평가가 아닙니다   |
| `boolean_or`            | `boolean_and_or` 의 `OR`    | 양쪽을 모두 읽고 `\|\|`                        |
| `color` · `text_color`  | (그대로 쓰입니다)           | 색 고르개 — 첫 칸의 `#rrggbb` 를 값으로 돌려준다 |

색 블록은 **지금도 쓰이는 값 블록**입니다. 붓 색·글자 색 블록의 칸을 채우는 것이 이것이라,
읽지 못하면 색이 `undefined` 로 들어가 그 블록이 조용히 아무 일도 안 합니다
(`witch.ent` 하나에 114개). 지금은 확장도 작품을 먼저 되돌리므로 `@tess/decompiler` 가
리터럴로 펴 놓지만, 블록 트리를 직접 넘겨받는 길(`Codegen` 을 따로 부르는 경우)에서는
그대로 나타납니다.

### `calc_operation` 은 어떤 연산자로도 옮긴다

엔트리의 단항 수학 블록입니다. 연산자는 `square`·`root`·`sin`·`cos`·`tan`·
`asin_radian`·`acos_radian`·`atan_radian`·`log`·`ln`·`unnatural`·`floor`·`ceil`·
`round`·`factorial`·`abs` 열여섯 가지이고, 엔트리는 **목록에 없는 연산자를 `round` 로
바꿔서** 계산합니다(`block_calc.js`) — 오류가 아닙니다.

`factorial` 만 Tess 에 이름이 없어서 되돌릴 때 자리표시자가 되었고, 그 한 가지 때문에
`calc_operation` 이 통째로 "모르는 블록" 으로 보고되었습니다. `factorial()` 을 내장
함수로 두어 그 구멍을 메웠고, 목록에 없는 연산자는 엔트리와 같이 `round` 로 읽습니다.
이제 이 블록은 어떤 연산자로 와도 알림이 나지 않습니다.

### 하드웨어 블록으로 만든 반복 건너뛰기 치트

`continue_repeat`(이번 반복 건너뛰기)를 **값 칸**에 끼운 블록이 널리 쓰입니다. 엔트리는
블록 자체보다 칸을 먼저 읽으므로 거기서 반복이 다시 돌고, 블록은 실행되지 않습니다.
프레임을 쓰지 않고 다음 차례로 넘어가는 `skip` 과 결과가 같고, 실을 것이 없는
하드웨어 블록(`Talebot_Move` 등)이 껍데기로 자주 쓰입니다(`cheatblock.ent`).

값 칸에 든 것이 전부 `continue_repeat` 이고 안에 문장을 담지 않은 블록은 **껍데기가
무엇이든 `skip` 으로 다룹니다** — 반복문 안에서는 `continue;`, 밖에서는 블록에 닿지도
않으므로 아무것도 하지 않습니다. `codegen` 과 `@tess/decompiler` 가 같은 규칙을 쓰고,
껍데기 블록은 "모르는 블록" 으로 세지 않습니다.

## 3. 값 — 엔트리의 산술은 2진수가 아니라 10진수다

엔트리의 `calc_basic` 은 **BigNumber** 로 계산합니다. 그래서 엔트리에서 `0.1 + 0.2` 는
`0.30000000000000004` 가 아니라 **`0.3`** 입니다. 이것을 무시하면 좌표·체력 계산이 조금씩
어긋나다가 비교식에서 갈라집니다.

BigNumber 를 그대로 쓰면 느리므로 `cast.ts` 는 같은 결과를 배정밀도만으로 냅니다.

- 양쪽이 정수면 그냥 계산합니다 — 이때 배정밀도 결과와 10진 결과는 항상 같습니다.
- 아니면 두 피연산자의 **소수 자릿수**로 결과를 되돌려 놓습니다
  (`Number(result.toFixed(p))`). 10진 결과가 가지는 자릿수가 `p` 이하이므로 이 반올림은
  정확히 그 값을 되찾습니다.
- 나누기는 BigNumber 가 20자리에서 끊으므로, 몫이 `1e-3` 보다 작을 때만 `toFixed(20)` 을
  거칩니다. 그보다 크면 배정밀도 나눗셈이 이미 같은 값입니다.

되돌리는 자리를 실제로 밟는 값은 많지 않습니다. `p` 자리 눈금이 그 크기의 **이웃 배정밀도
사이 간격보다 촘촘하면**, 그 눈금 위에는 결과가 이미 올라가 있지 않은 값이 없습니다 —
`toFixed(p)` 로 내려놓고 다시 읽어도 같은 배정밀도로 돌아옵니다. 간격의 엄밀한 하한은
`|x| * Number.EPSILON / 2` 이므로 `snap` 은 그 절반(`Number.EPSILON / 4`, `TENTHS[p]` 리터럴
자신의 오차까지 덮는 여유)으로 먼저 재고, 넘으면 문자열을 만들지 않고 결과를 그대로
돌려줍니다. 삼각함수가 낳는 16~17자리 값이 3D 작품 산술의 대부분이라 이 자리에서 걸립니다.

자릿수를 세는 `decimals` 도 정수면 `String` 없이 0 을 돌려주고(`1e21` 처럼 지수로 적히는
정수까지 같은 답), `isNumber` 은 `/^-?\d+\.?\d*$/` 를 문자 코드로 훑습니다. `num` 은
`parseFloat` 이 문자열만 받으므로 숫자는 텍스트로 나갔다 오지 않게 먼저 걸러 냅니다 —
최단 표기는 같은 배정밀도로 파싱되고, `NaN`·`-0` 은 어느 길로 가도 0, 무한대는 양쪽에서
살아남습니다.

`examples/ent/roblox.ent` 의 DirectX 장면에서 틱당 시간이 약 0.12ms 에서 0.09ms 로
내려갑니다(맵 0·3·7, 20000틱 3회 중 최선). 세 맵 1200프레임 동안의 변수·좌표·붓 좌표는
전부 같은 값이고, `toFixed` 기준 구현과 210만 쌍을 맞대어도 어긋나는 자리가 없습니다.

그 밖에 그대로 옮긴 규칙들:

| 자리                      | 규칙                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| 값 칸을 숫자로 읽기       | `parseFloat(v) \|\| 0` — `"12abc"` 는 12, `"abc"` 는 0            |
| 값 칸을 판단으로 읽기     | 숫자로 읽히면 그 진리값, 아니면 참 — `"0"`·`"0.00"` 만 거짓        |
| `같다`                    | 숫자로 읽히는 문자열은 숫자로 바꾼 뒤 **엄격 비교(`===`)**        |
| `같지 않다`               | 같은 변환 뒤 **느슨한 비교(`!=`)** — 엔트리의 비대칭을 그대로     |
| `+`                       | 양쪽이 숫자 꼴이 아니면 이어 붙이기                               |
| `그리고`·`또는`           | 두 쪽을 **모두 평가한 뒤** 결합 (엔트리는 단축 평가를 하지 않음)  |
| 나머지                    | 나누는 수의 부호를 따름 (`-1 mod 360 = 359`)                      |
| `변수 바꾸기`             | 결과를 `toFixed` 한 **문자열**로 저장 — 엔트리가 그렇게 합니다    |
| `사인`·`코사인`·`탄젠트`  | 30° 배수는 표에 든 정확한 값 (`Entry.preciseTrig`)                |

### `NaN` 은 값 칸을 지나면서 0 이 된다

`Entry.Scope.getNumberValue` 는 `parseFloat(v) || 0` 입니다. 숫자에 대해서도 `|| 0` 이
살아 있으므로, 앞 블록이 내놓은 `NaN` 은 **그 값을 읽는 다음 블록에서 0** 이 됩니다.
`0 / 0` 은 엔트리에서도 `NaN` 이지만, 그것을 곱하기의 한쪽 칸에 꽂으면 곱해지는 것은 0
입니다. 변수에 그대로 담을 때는 `getValue` 를 쓰므로 `NaN` 이 남습니다 — 두 자리를 가르는
것은 값을 **숫자로 읽었는가** 뿐입니다.

JIT 는 이미 숫자를 돌려주는 자리에 `n(...)` 을 씌우지 않지만, 그렇다고 변환을 통째로
빼면 `NaN` 이 식 끝까지 흘러갑니다. 그래서 `Value.kind` 가 `num` 인 자리에는 `n(...)`
대신 `(… || 0)` 을 답니다 — 같은 규칙이고 함수 호출도 없습니다.

실시간 변수에 `"null11111"` 같은 글자가 담긴 작품이 이 자리를 밟습니다
(`examples/ent/gomok.ent` 의 AI 승률: `짐 / (짐 + 이김)` 이 `0 / 0` 이라 `NaN` 이고,
곱하기 칸을 지나면서 0 이 되어 `AI 승률 : 0` 이 됩니다).

## 4. 프레임 속도 — `Entry.FPS` 는 작품이 정한다

엔트리는 작품을 열 때 `Entry.FPS = project.speed ? project.speed : 60` 으로 잡고, 그 값으로
두 가지를 한꺼번에 정합니다.

- **틱 간격** — `setInterval(Math.floor(1000 / FPS))`. 60 이면 16ms 라 실제로는 초당 62.5번
  돕니다(나머지가 버려집니다).
- **모든 '초 → 프레임' 환산** — `n초 동안 이동하기` 는 `floor(초 × FPS)` 프레임이고,
  `n초 기다리기` 는 `(60 / FPS) × 초 × 1000` ms 를 기다립니다.

그래서 `speed` 를 낮춘 작품은 그냥 느려지는 게 아니라 **프레임 수가 같은 채로 실제 시간이
늘어납니다**. `examples/ent/deltarune.ent` 가 `speed: 29` 라, 이 값을 무시하면 작품 전체가
두 배 빨리 돌아갑니다.

tessvm 도 같은 규칙입니다 — `vm.frameRate` 하나가 틱 간격과 환산을 함께 정합니다.

| 우선순위 | 값                                                   |
| -------- | ---------------------------------------------------- |
| 1        | `--fps <값>` (또는 `VmOptions.fps`)                  |
| 2        | 작품의 `project.speed` (Tess 의 `project: fps N`)    |
| 3        | 기본값 **64**                                        |

기본을 64 로 둔 것은 엔트리의 `setInterval(16ms)` 이 실제로 60 보다 빠르게 도는 것에
맞춘 값입니다. 화면은 `requestAnimationFrame` 으로 맞추되 틱은 이 속도로 고정하고, 한
프레임에 밀린 틱은 최대 4번까지만 따라잡습니다.

**초시계도 엔트리 규칙 그대로입니다.** `초시계 시작하기` 를 한 번도 안 했으면 값은 0 이고
`초시계 초기화` 는 아무 일도 하지 않습니다(`Entry.engine.resetTimer` 가 `isInit` 이 아니면
곧바로 돌아갑니다). 멈춘 채로 초기화하면 '한 번도 시작하지 않은' 상태로 되돌아갑니다.
시간은 실시간이 아니라 **엔진 시계**(`vm.clock`, 돌고 있는 동안만 틱마다 더해짐)로 재므로
일시정지하면 함께 멈추고, 헤드리스로 돌려도 결과가 같습니다.

## 5. 무대 크기 — 엔트리는 480×270 이지만 여기서는 정할 수 있다

무대 크기는 `src/runtime/model.ts` 의 `stage` 하나에만 있습니다. 충돌·벽·말풍선 위치·
변수 상자·렌더러·포인터 좌표가 전부 이 값을 읽으므로, `setStageSize(가로, 세로)` 한 번이면
전부 따라옵니다.

```bash
tessvm run game.ent --stage 960x540      # 명령줄에서
```
실행 페이지 머리줄의 **무대** 칸으로 돌리는 중에도 바꿀 수 있습니다.

- 좌표계는 언제나 `-가로/2 … 가로/2`, `-세로/2 … 세로/2` 입니다. 오브젝트 좌표는 그대로
  두고 **보이는 범위만 넓어집니다** — 480×270 에서 화면 밖이던 것이 보이게 됩니다.
- 무대 픽셀(충돌을 재는 공간)은 언제나 무대 단위의 4/3 배입니다. 엔트리가 480×270 을
  640×360 캔버스에 그리는 그 비율이라, 무대를 넓혀도 충돌 판정의 촘촘함은 그대로입니다.
- 벽(`wall_up` …)은 무대 밖 30단위 띠로 같이 움직입니다.

기본값은 480×270 이므로 아무것도 지정하지 않으면 엔트리와 완전히 같습니다.

## 6. 글상자 — 글꼴과 크기 재기

글상자는 크기가 곧 **잰 글자 크기**입니다. 엔트리는 `setText` 안에서
`setWidth(textObject.getMeasuredWidth())` 를 부르고, 그 크기를 `크기` 블록과 충돌 판정이
그대로 읽습니다. 그래서 tessvm 도 **VM 안에서 그 자리에 잽니다** — 렌더러가 다음 프레임에
고쳐 주는 방식이면 글을 쓰고 바로 크기를 읽는 코드가 한 프레임 뒤처진 값을 봅니다.

- `Project.measureTextBox` 로 재는 일을 렌더러에 물어봅니다. 브라우저에서는 PixiJS 의
  `CanvasTextMetrics` 로, **그릴 때 쓰는 것과 같은 스타일**로 잽니다.
- 줄바꿈을 켠 글상자는 작성자가 정한 크기를 그대로 씁니다(엔트리도 그렇습니다).
- 글꼴 문자열(`bold 16.54px DungGeunMo`)은 엔트리의 `setFont` 와 같은 순서로 읽습니다 —
  크기는 소수일 수 있으므로 `parseFloat` 로 뗍니다.
- 글꼴 이름은 엔트리처럼 **한 개만** 넘깁니다. 대체 글꼴 목록을 붙이면 브라우저가 재는
  줄 높이가 달라져서 글상자 크기가 어긋납니다.
- 실행 페이지는 엔트리가 쓰는 글꼴 CSS(`entry-cdn.pstatic.net/uploads/fonts/…`)를 그대로
  겁니다. 글꼴이 늦게 도착하면 PixiJS 가 캐시해 둔 잘못된 치수를 지우고(`clearMetrics`)
  글상자를 전부 다시 잽니다.
- 정렬은 글자를 옮기지 않고 **기준점**을 옮깁니다(`setTextAlign` 의 `anchor.x = [0.5,0,1]`).
  왼쪽 정렬이면 오브젝트의 x 에서 오른쪽으로 자랍니다 — 이걸 가운데 정렬로 그리면
  메뉴 글자가 화면 왼쪽으로 잘려 나갑니다.

## 7. 스스로를 멈추는 블록

엔트리에서 `복제본 삭제하기` 는 그 복제본의 **모든 실행기**를 끝냅니다
(`removeClone` → `clearExecutorsByEntity`). 그래서 그 블록을 함수 안에서 불러도 함수만
끝나는 게 아니라 부른 쪽까지 그 자리에서 멈춥니다. tessvm 은 `O.die()` 가 예외를 던져서
같은 자리에서 스택을 풀고, `Vm.runThread` 가 그것만 조용히 받습니다.

| 블록                            | 어디까지 멈추나                                  |
| ------------------------------- | ------------------------------------------------ |
| `복제본 삭제하기`               | 그 복제본의 스크립트 전부 (`O.die()`)            |
| `모든 코드 멈추기`              | 작품 전체 (`O.die()`)                            |
| `자신의 코드 멈추기`·`이 오브젝트의 다른 코드` | 그 오브젝트/복제본의 스크립트 (`O.die()`) |
| `이 코드 멈추기`                | **그 실행기만** — 함수 안이면 함수만 끝납니다     |
| `처음부터 다시 실행하기`        | 작품 전체를 멈추고 다시 시작                     |

### 값 함수 안의 `이 코드 멈추기` 는 반환식을 건너뛰지 않는다

`function_value` 는 본체 실행기가 끝나 있으면(`funcExecutor.isEnd()`) **그때 반환식을
계산해서 돌려줍니다**. `이 코드 멈추기` 는 `Scope.die()` 로 그 실행기만 끝내므로,
값 함수 중간에서 멈춰도 호출한 쪽이 받는 값은 `undefined` 가 아니라 **반환식의 값**입니다.

그래서 함수 본체는 이름표 붙인 블록으로 감싸고, 실행기를 끝내는 자리에서는 `return` 이
아니라 `break` 를 냅니다.

```js
F[0] = function* (e, th, P) {
  const L = { ... };
  fn: {
    ...
    if (조건) { break fn; }   // `이 코드 멈추기`
    ...
  }
  return L["res"];            // 멈춰도 여기까지 온다
};
```

`return` 으로 빠져나오면 값 함수는 늘 `undefined` 를 돌려줍니다. 델타룬의 대사 파서
`바보배열` 은 못 찾은 경우를 `res = "error"` 로 표시한 뒤 멈추고, 부르는 쪽은
`!= "error"` 로 가려냅니다. 반환값이 `undefined` 면 이 검사가 전부 참이 되어 문·벽·건물·
카메라 제한이 모두 엉뚱한 값으로 만들어집니다.

## 8. 장면을 넘어갈 때

`Entry.container.resetSceneDuringRun` 은 떠나는 장면의 오브젝트를 **처음 상태로 되돌립니다** —
스냅숏 복구(좌표·크기·회전·모양·글·보이기), 효과 초기화, 말풍선·붓·도장 지우기, 복제본
삭제, 스크립트 정지. tessvm 도 같은 순서로 합니다. 이걸 빼면 장면을 다녀온 뒤 오브젝트가
전에 있던 자리에 그대로 남습니다.

장면을 바꾸는 블록은 떠나는 장면의 실행기를 모두 지우므로 부르던 스레드도 거기서
끝납니다. 함수 안에서 불러도 마찬가지라 `O.die()` 로 스택 전체를 풉니다.

장면에 들어가면 `Entry.stage.sortZorder` 가 한 번 돌므로 tessvm 도 `sortScene()` 을
같은 자리에서 부릅니다.

### 다른 함수의 매개변수를 가리키는 블록

`stringParam_xxxx` 는 **도는 함수의** `register.paramMap` 에서 자리를 찾습니다
(`function_param_string` 의 본체가 `params[paramMap[this.block.type]]` 입니다). 그 맵은
함수마다 자기 머리말에서 만들어지므로, 작품을 짜다 다른 함수의 매개변수 블록을 끌어다
놓으면 그 자리에서 아무것도 찾지 못하고 **`undefined`** 가 됩니다.

그래서 되돌릴 때도 매개변수 이름은 **그 함수 안에서만** 풉니다. 남의 매개변수는 이름으로
적으면 그 함수에 없는 이름이 되어 컴파일이 그 문장을 통째로 버리고, 그러면 그 함수가
아무 일도 하지 않게 됩니다 — `examples/ent/chess.ent` 의 `find best move` 가 합법수를
구하는 줄을 잃고 `push(board, "0")` 로 판 문자열을 64 자에서 67 자로 늘리던 자리입니다.

### 신호 보내기는 프레임이 끝난 뒤에 올라간다

`message_cast` 의 본체는 `setTimeout(() => Entry.engine.raiseMessage(value))` 입니다. 신호를
올리는 일이 **매크로태스크로 밀려나므로**, 보낸 블록 다음 블록이 도는 동안에는 받는
스크립트가 아직 하나도 서 있지 않습니다. 엔트리의 틱은 `setInterval(update, tickTime)` 이라
그 타이머는 언제나 다음 틱 앞에서 돕니다 — 받는 쪽은 **다음 프레임**에 시작합니다.

`message_cast_wait` 는 반대로 `raiseMessage` 를 그 자리에서 부르고 실행기를 받아 둔 뒤
`script` 를 돌려줍니다(BREAK). 같은 프레임 안에 이미 받는 스크립트가 서 있습니다.

이 차이는 다음 짝에서 눈에 보입니다.

```
when start do
  send "모델"        # 신호는 아직 올라가지 않았다
  jump "이 장면"     # 이 장면의 실행기를 전부 지운다
end
```

`start_scene` 은 같은 장면을 골라도 `resetSceneDuringRun` 을 먼저 부르므로 그 장면의
스레드가 모두 끊깁니다. 신호가 그 자리에서 올라갔다면 받는 쪽도 여기서 함께 죽지만,
`setTimeout` 에 실려 있으므로 **장면 초기화를 지나 살아남아** 다음 프레임에 시작합니다.
3D 작품이 시작할 때 좌표 목록에 모델을 쌓아 두고 제목 장면으로 돌아가는 흔한 짜임이
이것에 기대고 있습니다 (`examples/ent/roblox.ent`).

그래서 `castMessage` 는 `vm.queueMessage(id)` 로 미뤄 두고, `tick()` 이 그 프레임의
오브젝트를 모두 돈 뒤 `flushMessages()` 가 올립니다. 올리는 시점의 장면을 보는 것도
`raiseMessage` 와 같습니다 — 보낸 뒤 다른 장면으로 넘어갔다면 새 장면이 받습니다.
실행을 멈추거나 되돌릴 때는 대기열도 함께 비웁니다.

### 글자 효과 칸은 엔트리 속성 이름 그대로다

`text_change_effect` 의 첫 칸은 `fontBold` · `fontItalic` · `underLine` · `strike` 입니다
(`EntityObject.applyEffectByNameAndValue` 가 그대로 switch 하는 이름). 굵게·기울임 같은
보기 좋은 이름으로 받으면 어느 가지에도 걸리지 않아 블록이 조용히 아무 일도 안 합니다.

## 9. 모양·소리 고르기 — 번호도 이름이다

`모양으로 바꾸기`·`소리 재생하기` 의 값은 **아이디 → 이름 → 1부터 세는 번호** 순으로
찾습니다(`Entry.EntryObject.getPicture`). 셋 다 아니면 **아무것도 아닙니다** — 첫 모양으로
떨어지지 않습니다.

```
모양을 "웃음" 으로 바꾸기   → 이름으로
모양을 2 로 바꾸기          → 두 번째 모양   ← 이걸 빠뜨리면 작품이 통째로 어긋난다
```

번호로 고르는 것은 애니메이션에서 흔합니다(`모양 번호 + 1` 로 돌리기). 이것을 못 찾고
첫 모양으로 떨어지면 얼굴·이펙트·UI 가 전부 엉뚱한 그림이 되고, 작품이 넣어 둔
`Missing`·`debug` 같은 자리표시 그림이 화면에 뜹니다. 번호가 범위를 벗어나면 `null` 이고,
`setImage(null)` 은 아무것도 하지 않으므로 이전 모양이 그대로 남습니다.

`Entry.parseNumber` 규칙도 그대로입니다 — `"007"` 처럼 `0` 으로 시작하는 값은 숫자가
아니라 이름으로 봅니다.

## 10. 그리는 순서 — 장면 하나에 납작한 목록 하나

엔트리는 장면마다 **표시 객체 하나짜리 납작한 목록**을 둡니다
(`Entry.stage.selectedObjectContainer`). 그 안에 오브젝트·복제본·붓 자국·도장이 **각각 제
자리**로 들어갑니다.

- 원본은 `sortZorder` 가 오브젝트 목록의 역순으로 깔아서, 목록 맨 위 오브젝트가 제일
  앞에 옵니다.
- 복제본은 `addCloneEntity` 가 **원본 바로 아래**에 끼워 넣습니다(원본의 붓·도장은 건너뜀).
- 붓과 도장도 그 오브젝트 바로 아래에 하나씩 들어갑니다. 붓(선)과 채우기는 **각각 처음
  쓰이는 순간에** 만들어져 그때의 오브젝트 자리에 끼워지므로, 나중에 집어 든 쪽이 먼저
  집어 든 쪽보다 앞에 옵니다. tessvm 은 층을 프레임 끝에 한꺼번에 만들기 때문에 그 순서를
  `BrushState.started` 로 따로 기억해 둡니다 — 정해진 차례로 돌면 판을 먼저 긋고 돌을
  채우는 작품에서 돌이 판 밑으로 들어가 사라집니다 (`examples/ent/gomok.ent` 에서 AI 가
  흑을 잡고 먼저 두는 판).
- `오브젝트 순서 바꾸기` 는 그 목록 안에서 **그 개체 하나만** 옮기며, 한 칸 움직일 때
  옆 개체의 붓·도장 수만큼 건너뜁니다.

그래서 **같은 오브젝트의 복제본이라도 깊이가 제각각**입니다 — 델타룬의 방에서는 가구
복제본 일부가 대화상자보다 뒤에, 일부가 앞에 있습니다. 복제본을 오브젝트별 층에 몰아
그리면 그 관계가 통째로 무너집니다(가구가 대화상자를 덮습니다). tessvm 도 장면마다 납작한
목록 하나를 두고 같은 규칙으로 끼워 넣습니다.

## 11. 충돌 — 같은 판정, 훨씬 적은 일

엔트리의 `~에 닿았는가?` 는 `ndgmr.checkPixelCollision` 으로 갑니다. 그 안에서 하는 일은

1. 두 스프라이트의 **월드 경계 상자**를 구해 겹치는 사각형을 찾고,
2. 그 사각형 크기의 **캔버스를 두 장 새로 만들어** 각 스프라이트를 world transform 그대로
   다시 그린 뒤,
3. `getImageData` 로 두 장의 알파를 읽어 **같은 자리에서 둘 다 51 을 넘는지**(임곗값 0.2)
   봅니다.

판정 한 번에 캔버스 두 장 + `drawImage` 두 번 + `getImageData` 두 번입니다. 총알 30개가
매 프레임 벽과 적을 확인하면 이것만으로 프레임이 무너집니다.

tessvm 은 **판정 결과는 그대로 두고 그리기만 없앱니다.**

- 모양마다 **알파 마스크**(픽셀당 1바이트)를 처음 한 번만 만들어 둡니다
  (`MaskStore`, 그 모양이 실제로 충돌에 쓰일 때 만듭니다).
- 겹치는 사각형은 엔트리와 **같은 640×360 무대 픽셀 공간**에서 같은 식으로 구합니다
  (무대 컨테이너가 `(320,180)`, 배율 `4/3` — `Entry.stage.initStage`). 그래서 판정의 해상도가
  화면 해상도와 무관하게 엔트리와 같습니다.
- 그 사각형을 한 픽셀씩 훑되, 픽셀마다 행렬을 곱하지 않고 **역변환의 증분만 더합니다**
  (한 픽셀에 덧셈 네 번). 두 마스크를 찾아보고 하나라도 맞으면 곧바로 끝냅니다.
- 마스크마다 **불투명한 부분의 경계 상자**를 재 두어 그 밖은 아예 보지 않습니다.
- 같은 프레임 안에서 같은 짝을 다시 물어보면 **캐시**로 답합니다. 키에는 두 오브젝트의
  `version`(좌표·크기·회전·모양이 바뀔 때마다 오르는 번호)이 들어가므로, 움직인 뒤에는
  캐시가 저절로 무효가 됩니다.

벽은 엔트리와 같습니다 — 무대 밖 30단위 띠 네 개(`bound.png` 는 알파가 없는 회색조 PNG 라
언제나 불투명)이고, `bounce_wall` 은 임곗값 0(알파 > 0), `reach_something` 은 0.2 입니다.
`bounce_wall` 의 "한 번 튕긴 벽은 떨어질 때까지 다시 튕기지 않는다" 상태 기계
(`entity.collision`)도 그대로 옮겼습니다.

마우스 판정은 엔트리의 PIXI 경로(`containsPoint` → `_pixelHasAlpha`, 알파 > 1)를 따릅니다.

**남는 차이 하나.** 엔트리는 캔버스에 다시 그리므로 크기를 줄인 스프라이트의 알파가
보간되어 옅어집니다. tessvm 은 마스크를 최근접으로 찾아봅니다. 크게 줄인 그림의 가장자리
한두 픽셀에서 판정이 갈릴 수 있고, 그 밖의 경우는 같습니다.

## 12. 렌더러 — 좌표는 엔트리 그대로, 화질만 올린다

무대 컨테이너를 엔트리와 똑같이 `(320,180)` 에 놓고 `4/3` 배로 키웁니다. 화질은 그 위에서
**`renderer.resolution` 만** 올립니다 — 캔버스 버퍼만 커지고 무대 좌표계는 640×360 으로
남으므로, 엔트리 코드에 픽셀 값으로 박혀 있는 위치들이 그대로 맞습니다.

```
resolution = (화면에 그려질 CSS 폭 / 640) × devicePixelRatio × 화질배수
```

즉 기본값(1×)에서 이미 **화면 픽셀 1:1** 입니다. 2×·4× 는 그 위에 초과 표본화를 얹습니다.

### 텍스처에 구워지는 것은 그 배율을 따라간다

무대에 바로 그려지는 png 모양과 달리, **글상자와 벡터 모양은 텍스처에 한 번 구워집니다.**
그 텍스처가 화면보다 성기면 확대되어 흐려지므로, 굽는 배율을 고정값이 아니라 화면이
요구하는 배율에서 가져옵니다.

```
무대 픽셀 하나에 들어가는 텍스처 픽셀 = 4/3 (무대 배율) × renderer.resolution
```

- **글상자**는 여기에 오브젝트 자신의 크기 배율까지 곱합니다 — 글상자는 컨테이너째
  확대되므로, 2배로 키운 글상자는 두 배 촘촘한 텍스처가 있어야 같은 선명도입니다.
  하한 2배(작게 그려지는 글상자도 이 아래로 내려가지 않습니다), 상한 8배.
- **벡터 모양**은 하한 2배, 상한 4배입니다. 한 작품이 든 모양은 글상자보다 훨씬 많아
  전부가 텍스처로 남기 때문입니다. 여기에 픽셀 상한(긴 변 4096px, 넓이 2048×2048)과
  아래의 **작품 전체 예산**이 걸립니다.
- 두 배율 모두 **0.5 단위로 올림**합니다. 창을 끌어 크기를 바꾸는 동안, 또는 크기가
  변하는 글상자에서 매 프레임 텍스처를 다시 굽지 않게 하기 위해서입니다.

어느 쪽이든 **한 변 4096px** 을 넘지 않습니다(벡터는 넓이 2048×2048 도 함께). 모든 webgl
구현이 보장하는 크기라, 넘겨 달라고 하면 업로드가 실패하고 그 글상자 하나가 아니라
**렌더러가 통째로 죽습니다.** 상한은 하한보다 뒤에 걸리므로, 이미 상한을 넘는 큰 그림은
안 그려지는 대신 제 크기보다 작게 구워집니다.

#### 벡터 텍스처 예산 — 한 장이 아니라 작품 전체를 본다

한 장에 걸리는 상한만으로는 부족합니다. 960×540 벡터 하나는 상한 안에서도 16MB 를
차지하므로, 그런 모양을 백 장 든 작품은 1.6GB 를 요구합니다. 카드가 담지 못하면 매
프레임을 그리는 대신 텍스처를 옮기는 데 쓰고, 프레임이 눈에 띄게 떨어집니다.

그래서 `preload` 가 작품이 든 벡터(`imageType === 'svg'`)의 이름 크기를 모아, 전부
합쳐서 `SVG_PIXEL_BUDGET`(64M 픽셀 · 256MB)에 들어가는 배율(`svgBudgetScale`)을 구하고
모든 벡터의 배율에 함께 곱합니다. 배율은 제곱해서 픽셀이 되므로 남은 자리는 제곱근으로
나눕니다 — 모양이 두 배면 각자 `1/√2` 배입니다.

상한과 0.5 단위 올림이 실제 배율을 다시 움직이므로 한 번에 맞지 않습니다. 예산은 실제로
차지하는 크기를 다시 재어 가며 최대 여덟 번 조입니다(`fitSvgBudget`). 하한은 1배로,
그 아래는 옆에 있는 래스터와 다를 것이 없습니다. 캔버스 크기가 바뀌면 요구 배율이
달라지므로 다시 굽기 전에 예산도 다시 맞춥니다.

| 작품                | 예산 없이 | 예산 안에서 |
| ------------------- | --------- | ----------- |
| 무대 크기 벡터 1장  | 16MB      | 16MB (그대로) |
| 무대 크기 벡터 60장 | 960MB     | 267MB       |
| 200×200 벡터 500장  | 687MB     | 172MB       |

캔버스가 커져서 `renderer.resolution` 이 오르면(창 크기·전체 화면·화질 배수) 글상자는
다음 `flush` 에서 다시 구워지고, 벡터 모양은 필요한 배율이 구워 둔 것보다 1.25배를 넘을
때 다시 받아 굽습니다. 다시 구울 때는 주소 뒤에 배율을 붙여 새 텍스처를 만들고 다 된 뒤에
바꿔 끼우므로, 화면에 있는 텍스처가 도중에 비는 일이 없습니다. 바꿔 끼운 뒤에는 **이전
배율의 텍스처를 `Assets.unload` 로 놓아 줍니다** — 놔두면 창 크기를 바꿀 때마다 카드에
한 벌씩 쌓입니다. 다시 굽는 것도 처음 받을 때와 같이 12개씩 나눠서 합니다. 한꺼번에
던지면 벡터가 많은 작품은 다 될 때까지 프레임을 흘립니다. **충돌 마스크는 처음 받은
그림 그대로 둡니다** — 창 크기 때문에 판정이 달라지면 안 됩니다.

**모양은 첫 장면 것만 기다립니다.** 작품 하나가 그림 2천 장을 들고 있기도 한데
(`deltarune.ent` 는 2,049개), 그것을 한꺼번에 요청하면 브라우저가 통째로 멈춥니다. 지금은
지금 장면에 필요한 것만 12개씩 나눠 받고 기다리며, 나머지는 뒤에서 흘러 들어옵니다.
소리도 같은 방식(6개씩)입니다. 아직 안 온 모양은 스프라이트가 비어 있다가 도착하면
그때 채워집니다.

**상태 반영은 프레임 끝에 한 번만 합니다.** VM 이 좌표를 바꿀 때 하는 일은 `entity.dirty`
를 세우는 것뿐이고, `flush()` 가 그 프레임에 실제로 달라진 오브젝트만 PIXI 에 옮깁니다.
엔트리는 `setX` 한 번에 PIXI 속성을 바로 건드리고 `updateDialog`·`updateCoordinateView`
까지 부르므로, 한 프레임에 좌표를 여러 번 바꾸는 코드에서 차이가 큽니다.

효과(밝기·색깔·투명도)는 엔트리가 만드는 것과 **같은 색 행렬**을 씁니다. 밝기는
`값/255` 를 오프셋 열에 넣고(`GEHelper.colorFilter.brightness`, pixi 의 `_loadMatrix` 는
`multiply=false` 일 때 정규화를 하지 않으므로 이 나눗셈이 곧 정규화입니다), 색깔은
`hsv` 값에 따라 채널을 돌리는 세 가지 행렬 중 하나입니다.

말풍선은 `Entry.Dialog` 의 값을 그대로 씁니다 — 15px 글자, 여백 10, 흰 바탕에 `#4f80ff`
2px 테두리, 꼬리는 오브젝트 경계 상자를 기준으로 네 방향(`nw`·`ne`·`sw`·`se`) 중 하나.

### 슬라이드 변수 — 상자 아래 붙는 슬라이더

`variableType: "slide"` 인 변수는 상자가 24 가 아니라 **42 높이**이고, 이름·값 칸 아래에
회색 활주로와 손잡이가 붙습니다(`Entry.SlideVariable.updateView`).

| 자리          | 엔트리                                                  |
| ------------- | ------------------------------------------------------- |
| 상자          | `rr(0, -14, max(이름폭 + 값폭 + 35, 90), 42, 4)`        |
| 활주로        | `rr(6, 16, maxWidth + 4, 5, 2)`, `#d8d8d8`              |
| `maxWidth`    | `max(이름폭 + 값폭 + 26, 90) - 16`                      |
| 손잡이        | 9×20 그림을 0.8 배, `y = 9`, `regX = 0.5`               |
| 손잡이 자리   | `getSlidePosition = maxWidth * 비율 + 6`                |

값을 바꾸는 규칙도 그대로입니다. 활주로를 누른 자리를 상자 왼쪽에서 잰 `commandX` 로
바꾸고 `[10, maxWidth + 10]` 으로 자른 뒤, `(commandX - 10) / maxWidth` 비율을 최솟값과
최댓값 사이에 놓고 소수점 두 자리로 반올림합니다. 두 끝이 모두 정수면 정수로 떨어집니다.

Tess 에는 `var depth = 2 from 0 to 4` 로 적습니다 — `from`·`to` 는 이미 있는 낱말이라
새 예약어가 늘지 않습니다. 컴파일러가 `variableType: "slide"` 와 `minValue`·`maxValue` 로
내보내고, 되돌릴 때도 같은 꼴로 돌아옵니다(`examples/ent/chess.ent` 의 `탐색 깊이 설정`).

### 자리를 정하지 않은 변수 상자

`Variable.generateView` 는 작품이 상자 자리를 적어 두지 않았을 때만 스스로 놓습니다.
값 상자와 리스트 상자는 **따로 세고**, 값 상자는 한 줄에 11개씩 24 간격으로 쌓다가
다음 줄을 80 오른쪽·264 위에서 시작합니다. 리스트 상자는 6개씩 110 간격입니다. 세는
수가 그 상자의 **자기 종류 안에서의 자리**여야 합니다 — 전체 개수로 세면 뒤쪽 상자가
무대 아래로 밀려나 아무것도 보이지 않습니다.

### 도장은 텍스처가 아니라 모양의 크기로 찍힌다

벡터 모양은 자기 크기보다 촘촘하게 구워지므로 텍스처 크기가 모양 크기와 다릅니다.
스프라이트는 `width` 를 넣어 두면 픽시가 그 비율을 알아서 잡지만, 도장은 오브젝트 배율도
함께 걸리므로 **두 배율을 곱해야** 합니다. 배율을 그냥 덮어쓰면 구운 배율만큼 어긋나서,
`examples/ent/chess.ent` 의 체스판 칸이 제 크기의 1/2.5 로 찍혔습니다. 회전 기준점도
스프라이트 안쪽 좌표(=텍스처 픽셀)로 읽히므로 같은 비율로 나눠 줘야 합니다.

### 붓 — 끝은 각지고, 한 무리는 한 번만 겹친다

**끝과 모서리는 각집니다.** 엔트리는 `setStrokeStyle(굵기)` 만 부르고 나머지는
createjs 기본값에 맡깁니다 — 기본값이 `butt` 끝과 `miter` 모서리라, 붓 자국은 시작한
자리에서 정확히 끊기고 꺾인 곳은 뾰족합니다. 둥근 끝(`round`)으로 그리면 굵은 붓일수록
양 끝이 반지름만큼 삐져나옵니다.

**투명도는 선과 채우기에 함께 걸립니다.** 색·굵기 블록은 각각 붓과 채우기 하나만
건드리지만, `붓의 투명도` 두 블록은 `sprite.brush` 와 `sprite.paint` 를 둘 다 바꿉니다
(`block_brush.js` 의 `set_brush_tranparency` · `change_brush_transparency`).

**투명한 붓은 겹쳐도 진해지지 않습니다.** 엔트리는 색·굵기·투명도가 바뀔 때까지 하나의
캔버스 경로에 계속 이어 그리고 그 경로를 **한 번에** 칠합니다(`endStroke` →
`beginStroke`). 그래서 그 무리 안에서는 스스로 교차하든, `그리기 멈추기` 뒤에 다시
이어 그리든 한 겹으로만 보입니다. PIXI 는 획을 삼각형으로 펴서 그리므로 겹친 자리가
두 번 칠해집니다 — 같은 무리를 한 번의 `stroke()` 로 묶어도 마찬가지입니다(브라우저에서
확인했습니다).

그래서 무리마다 컨테이너를 하나씩 두고, **투명한 무리는 그 컨테이너를 텍스처로 한 번
구운 뒤(`cacheAsTexture`) 그 텍스처에 투명도를 겁니다.** 불투명한 무리(투명도 0 —
기본값)는 겹쳐도 달라지지 않으므로 굽지 않습니다. 무리가 그대로면 다시 그리지 않아서,
붓을 끌고 다니는 동안 텍스처를 새로 굽는 것은 지금 그리는 그 무리 하나뿐입니다.

엔트리와 나란히 놓고 픽셀을 재서 맞췄습니다 — 투명도 50 인 획의 가운데와 꺾인 자리,
투명도 80 인 획이 겹친 자리, 굵은 획의 끝에서 반 굵기만큼 바깥 — 네 자리 모두 두
실행기가 같은 색을 냅니다.

### 붓은 프레임마다 한 번만 다시 그린다

붓은 **점을 찍을 때마다** 렌더러에 알립니다(`ops.pen` → `penChanged`). 그 자리에서
바로 다시 그리면, 다시 그리는 일이 그 개체의 획을 처음부터 훑는 일이라 한 프레임이
점 개수의 **제곱**만큼 듭니다. 그래서 `penChanged` 는 `penDirty` 에 표시만 하고,
프레임마다 한 번 도는 `flush` 가 몰아서 그립니다(엔트리도 붓 층은 프레임마다 한 번
그립니다).

측정 — bad apple(한 프레임에 폴리곤 수백 개를 `go` 로 찍는 작품, 60fps):

| | 11초·12초의 틱 수 | 붓 처리 시간 |
| --- | --- | --- |
| 점마다 다시 그리기 | 48 · 50 (60이어야 함) | 최대 645 ms/초 |
| 프레임마다 한 번 | 60 · 60 | — (틱 전체가 최대 112 ms/초) |

지우기(`brush_erase_all`)와 개체 삭제는 표시를 같이 지웁니다 — 그려 넣을 층이 이미
사라진 뒤라 되살릴 것이 없습니다.

### 도는 작품의 키는 페이지가 보지 못한다

엔트리는 작품이 도는 동안 **모든 키의 기본 동작을 막습니다**
(`Entry.Utils.captureKeyEvent`: `isState('run')` 이면 `e.preventDefault()`). 이것이 없으면
space 가 탭을 내리고 방향키가 페이지를 스크롤해서, 무대가 눈앞에서 움직여 버립니다.
`bindInput` 의 `worksKey` 가 같은 판단을 합니다.

| 그 키를 누가 갖는가 | 조건                                        |
| ------------------- | ------------------------------------------- |
| 작품                | `vm.state === 'run'` 이고 아래에 걸리지 않음 |
| 페이지              | 작품이 멈췄거나 일시정지 — `fireEvent` 도 그때는 아무것도 하지 않는다 |
| 그 칸               | 이벤트 대상이 입력칸·단추·고르는 칸·편집 가능한 곳 |
| 브라우저            | ctrl·alt·cmd 를 쥔 조합 (그 키 자체가 조합키면 작품의 것) |

작품의 것이 된 키는 `preventDefault` 와 `stopPropagation` 을 같이 받습니다. 확장은
`keyTarget` 을 실행기로 두지만 그 뒤로 페이지가 그대로 있어서, 막기만 하면 playentry 의
단축키가 여전히 듣습니다.

키 이벤트의 `target` 은 언제나 포커스를 쥔 것이라, 대상의 태그만 보면 충분합니다 —
조상까지 훑으면 실행기가 놓인 자리에 따라 판단이 달라집니다.

### 프레임 루프 — 탭이 뒤로 가면 워커가 몬다

`requestAnimationFrame` 은 탭이 숨겨지는 순간 **아예 멈춥니다.** 그러면 작품이 그 자리에
얼어붙고, 돌아왔을 때 그 사이 시간이 통째로 사라져 있습니다. 숨은 페이지의 타이머는
1초에 한 번(한참 뒤에는 1분에 한 번)으로 묶이지만 **전용 워커의 타이머는 묶이지 않아서**,
`boot.ts` 의 `startFrameDriver` 가 `visibilitychange` 를 보고 둘을 갈아 끼웁니다 — 보일
때는 rAF, 숨으면 워커. `vm.advance` 는 넘겨받은 시각으로 자기 시계를 맞추므로, 어느
쪽이 몰든 한 바퀴는 똑같이 `1000 / frameRate` 입니다.

측정: 숨긴 탭에서 60fps 그대로 돕니다(rAF 만 쓰면 0fps). 워커를 못 만드는 곳(페이지 CSP
등)에서는 평범한 `setInterval` 로 떨어지고, 그때는 브라우저가 묶는 만큼만 돕니다.

엔트리 실행기(`--entry`)는 손대지 않았습니다. 그쪽은 entryjs 가 자기 `setInterval` 로
몰고, 숨은 탭에서 느려지는 것까지가 진짜 엔트리의 행동이라 비교 기준으로 그대로 둡니다.

### 캔버스 크기 맞추기 — 자기 크기를 되먹이지 않는다

캔버스의 CSS 크기는 무대 상자(`.tessvm-stage`)에 16:9 로 꽉 차게 맞춥니다. 이때 지켜야
하는 규칙이 하나 있습니다 — **재는 상자의 크기가 캔버스를 따라가면 안 됩니다.**

`ResizeObserver` 로 무대 상자를 지켜보다가 그 콜백에서 캔버스 크기를 쓰는데, 상자가
캔버스를 감싸고 있으므로 상자 크기가 내용(캔버스)에서 나오면 그 값이 곧바로 같은
옵저버로 되돌아옵니다. 게다가 `Math.floor` 로 픽셀을 내림하므로 한 번 돌 때마다 1px 씩
작아지면서 여러 번 되풀이되고, 브라우저는 그 프레임에 다 전하지 못한 알림을
`ResizeObserver loop completed with undelivered notifications.` 오류로 알립니다.

세 겹으로 끊었습니다.

1. **무대 상자가 남은 자리를 스스로 채웁니다.** `main` 은 `place-items` 를 늘림(stretch)
   그대로 두어 `#stage` 가 남은 자리를 차지하고, 가운데 정렬은 그 안쪽(`.tessvm-stage`)
   에서 합니다. 상자 크기가 캔버스와 무관해지므로 되먹임 자체가 없어집니다.
2. **크기가 그대로면 다시 배치하지 않습니다.** 잰 값이 지난번과 같으면 아무 일도 하지
   않습니다(화질을 바꿨을 때처럼 강제로 다시 맞춰야 하는 길은 따로 있습니다).
3. **배치는 옵저버 안에서 쓰지 않습니다.** `requestAnimationFrame` 으로 한 프레임 미뤄서,
   알림을 전하는 도중에 레이아웃을 건드리지 않습니다.

실행 페이지는 그래도 혹시 남는 이 알림을 빨간 오류 상자에 띄우지 않고 콘솔에만
남깁니다 — 예외가 아니라 "이번 프레임에 다 전하지 못했다" 는 알림이기 때문입니다.

캔버스에 그릴 이유가 없는 것은 HTML 로 둡니다. **물어보기 입력창**과 **차트 창**이
그렇습니다. 엔트리는 `CanvasInput` 으로 캔버스에 직접 그리기 때문에 해상도를 올리면
크기가 어긋나 `scaleInputFieldToBuffer` 같은 보정이 필요했지만(AI_README.md), HTML
`<input>` 은 해상도와 무관하게 선명하고 모바일 키보드도 그대로 뜹니다.

**자리와 크기는 엔트리 그대로입니다.** `Entry.stage.showInputField` 는 640×360 캔버스의
`(15, 275)` 에 546×50 상자를 놓고, 그 뒤에 54×54 확인 단추
(`images/stage/submit.svg` — 파란 사각형에 흰 체크)를 붙입니다. 그래서
`src/web/ask-style.ts` 는 전부 무대에 대한 비율로 씁니다(왼쪽 2.344%, 위 76.389%,
너비 95.625%, 높이 15%). 비율로 쓸 수 없는 값 — 글자 20px, 모서리 10px, 테두리 2px —
은 `--tessvm-stage-width` 를 읽습니다. 캔버스를 배치할 때마다 `boot()` 이 그 폭을
써 넣으므로, 무대를 키워도 입력창이 같은 비율로 커집니다.

이 스타일은 입력창을 만드는 쪽인 tessvm 이 들고 있습니다. 실행 페이지와 확장이 각자
베껴 쓰면 한쪽만 고쳐져 어긋납니다.

### 차트 창 — 엔트리도 모달이다

`테이블 차트 창 열기` 가 여는 창은 `src/web/chart-view.ts` 가 만듭니다. 엔트리 역시
캔버스가 아니라 DOM 모달을 띄웁니다 — `DataTable.createChart` 가 `entry-table-chart`
div 를 만들고 거기에 `ModalChart` 를 올립니다.

창틀·이름줄·계열 표시·드롭다운은 HTML 이고, 그림만 SVG 입니다. 좌표는 그릴 자리를 잰
픽셀 그대로여서 눈금 글자가 늘어나지 않고, 창 크기가 바뀌면 `ResizeObserver` 가 다시
그립니다. 글자 크기는 입력창과 같은 `--tessvm-stage-width` 를 따르므로 무대를 키우면
창도 같은 비율로 커집니다.

**작품이 담은 글자는 `textContent` 로만 넣습니다.** 표 이름·차트 제목·열 이름·칸 값은
모두 작품이 준 것이므로, 마크업으로 읽히는 자리(`innerHTML`)에는 넣지 않습니다. SVG
속성에 들어가는 값은 전부 우리가 낸 수치이거나 우리가 고른 색입니다.

캔버스 오버레이는 차트를 그리지 않습니다 — `Overlay.showTable` 은 차트 번호가 없는
창(`chart === null`)만 그립니다. 열려 있는 동안 표가
바뀌면 `Table.revision` 이 올라가고, 프레임마다 부르는 `sync()` 가 그것을 보고 다시
그립니다.

### 말풍선 — 15자마다 끊는다

`new Entry.Dialog` 는 받은 글을 **`message.match(/.{1,15}/g).join('\n')`** 로 바꿉니다.
15자마다 줄을 끊는 것이라, 긴 글도 말풍선이 무대 밖으로 넓어지지 않습니다. 이것을
빼면 한 줄짜리 긴 말풍선이 되어 `placeDialog` 의 무대 안쪽 보정에 걸려 엉뚱한 자리로
밀립니다. 같은 정규식이 원래 있던 줄바꿈도 같이 없앱니다(`.` 이 줄바꿈에 걸리지 않아
경계로만 쓰입니다).

`물어보기` 의 말풍선은 `말하기` 와 **같은 모양**입니다 — 엔트리도 `'speak'` 와 `'ask'` 를
한 가지로 그립니다(`생각하기` 만 동그란 꼬리). 엔트리는 입력창을 먼저 얹고 말풍선을
그 위에 그리지만, 여기서는 입력창이 HTML 이라 말풍선 위에 옵니다. 무대 아래쪽에 놓인
말풍선이 입력창에 가려지는 것은 그 차이입니다.

### 벡터 모양은 언제 벡터로 쓰는가

엔트리의 벡터 편집기로 그린 모양은 서버에도 `.ent` 안에도 **두 벌**(`.svg`·`.png`)로
들어 있고, 엔트리 실행기는 언제나 `.png` 쪽을 씁니다(`AtlasImageLoadingInfo` 가 확장자를
`.png` 로 박아 둡니다). tessvm 은 벡터가 **정말로 이득일 때만** 벡터를 씁니다.

| 조건                              | 왜                                                                    |
| --------------------------------- | --------------------------------------------------------------------- |
| svg 자체 크기 == 작품의 `dimension` | 편집기가 저장할 때 화면을 다시 잡는데 그 결과는 png 에만 남습니다. 크기가 다르면 벡터는 **늘어나 보입니다** |
| 960×540 이하                      | 편집기 캔버스 크기. 넘으면 다시 잡힌 그림입니다                       |
| `<image>` 가 없다                 | base64 png 를 감싼 껍데기입니다. 픽셀을 다시 픽셀로 만드는 셈이고 파일도 몇 배 큽니다 |
| `<text>` 가 없다                  | 이미지로 불러온 svg 는 자기만의 문서에서 그려져 **페이지의 웹폰트에 닿지 못합니다.** 글자가 대체 글꼴로 나옵니다 |

실제 작품(`witch.ent`)의 svg 1454개 중 이 넷을 모두 통과하는 것은 **60개**입니다.
1112개가 `<image>` 껍데기, 449개에 `<text>` 가 있습니다. 이걸 가리지 않고 전부 벡터로
쓰면 그림이 흐려지고 늘어나며, base64 를 데이터 URL 로 디코딩하느라 프레임도 무너집니다.

통과한 모양은 화면이 요구하는 배율(최소 2배, 최대 4배)로 래스터화합니다. 1배로 만들면
옆에 있는 png 와 픽셀 수가 같아서, 캔버스를 한 번 거치는 손해만 남습니다. 배율을 정하는
규칙은 12장 '텍스처에 구워지는 것은 그 배율을 따라간다' 에 있습니다.

`<text>` 가 든 svg 에 png 사본이 없으면 어쩔 수 없이 svg 를 씁니다. 이때는
`document.fonts.ready` 를 기다린 뒤 불러오지만, **기다려도 글꼴은 적용되지 않습니다** —
이미지로 쓰인 svg 는 바깥 자원을 전혀 받지 못하는 문서에서 그려지기 때문입니다. 기다리는
것은 png·mp3 에는 걸지 않습니다.

끄는 방법은 `tessvm run --no-svg`, 확장 팝업의 '벡터 모양 그대로 쓰기' 스위치입니다.
`@tess/decompiler` 도 `.ent` 를 풀 때 같은 규칙으로 어느 파일을 쓸지 정하고, 통과한
모양은 png 사본을 옆에 함께 남겨 실행기가 고를 수 있게 합니다(`--keep-svg` 는 예외로
벡터만 남깁니다).

### 변수 상자 색은 종류마다 다르다

`_adjustSingleViewBox` 가 값 칸 색을 종류별로 넘깁니다.

| 상자   | 색        |
| ------ | --------- |
| 변수   | `#4f80ff` |
| 대답   | `#F57DF1` |
| 초시계 | `#f4af18` |

### 로컬 실행 페이지는 아무것도 기다리지 않는다

`boot({ waitForAssets: false })` 는 모양도 소리도 기다리지 않습니다. `tessvm run` 이 띄우는
페이지가 이렇게 돕니다 — 파일이 이 기계의 디스크에서 오므로 앞에 세워 둘 이유가 없습니다.
덮개에는 **시작 단추 하나**만 있고 로딩 문구가 없습니다.

파일은 그대로 다 요청합니다. 기다리지 않을 뿐이고, 단추를 누를 때까지 뒤에서 들어옵니다.
안 온 모양의 스프라이트는 아무것도 그리지 않으니 그동안 닿음 판정에도 걸리지 않고,
도착하면 그 자리에서 채워집니다. 늦게 온 소리만은 되돌릴 수 없는데(그것을 멈추라던 정지·
장면 전환이 지나간 뒤에 울립니다), 같은 기계에서 오는 파일이라 그 창이 사실상 없습니다.

이미지 응답에 300ms 를 얹은 프록시 뒤에서 `ovenpark.ent`(모양 210 · 소리 5)를 재보면
시작 단추가 열리는 시점이 **12.7초 → 8.5초** 이고, 그때 모양은 165/210 이 들어와 있고
12개가 오는 중입니다. 남은 시간은 에셋이 아니라 **모듈을 받고 렌더러를 세우는 시간**입니다
(JIT 컴파일은 이 작품에서 11ms 입니다).

확장은 기본값 그대로 둘 다 기다립니다 — 남의 서버에서 오고, 늦게 오는 소리가 실제로
어긋납니다(AI_EXTENSION.md 4장).

### 다 받은 뒤에 시작한다

`Entry.initSound` 가 작품을 열 때 소리를 **전부** 큐에 넣고, 실행기는 그것이 끝난 뒤에
돕니다. 모양도 마찬가지로 로딩 막대 뒤에서 다 받습니다. 그래서 엔트리에서
`소리 재생하기` 는 언제나 손에 파일을 들고 있는 상태입니다.

tessvm 도 같습니다 — **모양과 소리가 전부 도착하기 전에는 작품이 돌지 않습니다.**
`boot()` 이 그때까지 돌아오지 않고, `onProgress` 로 진행률을 알려 줍니다(확장은 시작
단추를 그때까지 숨기고, 실행 페이지는 시작 단추에 퍼센트를 씁니다). 첫 장면 것을 먼저
받으므로 첫 화면은 일찍 준비됩니다.

기다리지 않으면 실행 초반의 재생 요청이 전부 비동기 경로로 가고, 파일이 도착하는 순서가
`모든 소리 멈추기`·장면 전환과 뒤엉킵니다 — **장면 1 에서 시켰던 소리가 장면 2 에서
튀어나옵니다.** 모양도 한 프레임 늦게 튀어 들어옵니다.

그래도 남는 경우를 위한 안전장치가 둘 더 있습니다.

- 아직 로딩 중인 재생 요청은 `stopAll`·`stopBgm`·`stopEntity`·`stopExcept` 가 **취소표를
  찍습니다**. 도착해도 시작하지 않습니다.
- 배경음은 한 줄기뿐입니다. `playBgm` 이 먼저 `stopBgm` 을 부르지 않으면, 로딩 중에 두 번
  부른 곡이 겹쳐서 울리고 나중 것만 멈출 수 있게 됩니다.

**일시정지는 소리를 멈춥니다.** `Entry.engine.togglePause` 가
`Entry.Utils.pauseSoundInstances` 로 재생 지점을 그대로 붙잡아 두므로, 여기서도 오디오
컨텍스트를 `suspend()` 했다가 이어서 할 때 `resume()` 합니다(`ensure()` 가 그 사이에
되살리지 않도록 `paused` 를 봅니다). 읽어주기도 같이 멈췄다 이어집니다.

### 소리와 배경음악은 서로 다른 목록이다

엔트리는 재생 중인 것을 `Entry.soundInstances` 와 `Entry.bgmInstances` 두 목록에 나눠
담습니다. **소리 크기·재생 속도·소리 멈추기 블록은 앞의 목록만 훑습니다.**

| 블록                    | 엔트리가 하는 일                                | 배경음악에 닿는가 |
| ----------------------- | ----------------------------------------------- | ----------------- |
| `모든 소리 멈추기`      | `Entry.Utils.forceStopSounds()`                 | 아니다            |
| `이 오브젝트의 소리...` | `Entry.soundInstances.getAll(entity)`           | 아니다            |
| `다른 오브젝트의...`    | `Entry.soundInstances.getAllExcept(entity)`     | 아니다            |
| `소리 크기 정하기`      | `soundType` 이 없는 인스턴스에만 volume 을 쓴다 | 아니다            |
| `소리 속도 정하기`      | `Entry.playbackRateValue` + 위와 같은 목록      | 아니다            |
| `배경음악 멈추기`       | `Entry.Utils.forceStopBGM()`                    | 이것만 닿는다     |

그래서 재생기는 배경음악을 `playing` 에 넣지 않고, 소리 크기를 걸어 둔 `master` 게인도
거치지 않고 `destination` 에 바로 잇습니다. `Entry.Utils.playBGM` 은
`createjs.Sound.play(id, { volume: 1 })` 이므로 **반복하지 않고 속도도 언제나 1** 입니다.

`읽어주기` 는 배경음악이 아니라 소리 쪽입니다 — 엔트리가 `soundType: 'tts'` 를 붙여
`soundInstances` 에 `global` 키로 넣으므로, `이 오브젝트의 소리 멈추기`만 빼고 모두
닿습니다.

### 장면을 바꾸면 소리가 멎는다

`Entry.scene.selectScene` 은 실행 중에 장면이 실제로 바뀌면 `Entry.Utils.forceStopSounds()`
를 부릅니다(배경음악은 그대로 둡니다). 장면을 떠나면 그 장면의 스크립트가 모두 멎으므로,
소리를 멈춰 줄 코드도 함께 사라진다는 것이 이유입니다.

이것이 없으면 `장면 시작하기` 로 오간 횟수만큼 같은 곡이 겹칩니다 — 예를 들어 `무한 반복
{ 소리 재생하고 기다리기 }` 로 배경음을 까는 작품에서 죽고 다시 시작하기를 네 번 하면
여섯 줄기가 한꺼번에 울립니다. 겹친 뒤에는 `모든 소리 멈추기`를 넣어도 다음 장면 전환에서
다시 겹치므로, 작품 쪽에서는 손쓸 방법이 없습니다.

`Entry.stage.hideInputField` 도 같은 자리에 있습니다. `묻고 기다리기` 로 열린 입력칸은
그것을 기다리던 스크립트와 함께 내려갑니다.

### 읽어주기 목소리

엔트리의 `읽어주기` 는 클로바 목소리(`kyuri`·`jinho`·`hana`·`dinna`·`brown`·`minions`·
`sally`·`nsabina`·`nmammon`·`nmeow`·`nwoof`)를 씁니다. 브라우저의 `speechSynthesis` 로는
그 목소리를 낼 수 없으니, **한국어 목소리를 골라 놓고** 화자마다 높이와 빠르기만 다르게
줍니다. 목소리를 고르지 않으면 브라우저 기본값(대개 영어)이 한글을 읽어서 알아들을 수 없는
소리가 납니다. 목록은 처음에 비어 있을 수 있으므로 `voiceschanged` 를 한 번 기다립니다.

### 리스트 상자 — 끌어서 넘긴다

`Entry.ListVariable` 은 스크롤 단추를 끌어 목록을 넘깁니다. 여기서는 포인터가 한 길로만
들어오므로, 리스트 상자 안에서 누르면 그 눌림은 작품에 전해지지 않고 목록을 넘깁니다.

- **옆의 바**를 잡으면 바가 지나는 길이만큼이 목록 전체가 됩니다.
- **항목 쪽**을 잡으면 20px 당 한 줄씩 손을 따라옵니다.

바가 지나는 길(`barRun`)은 그리는 쪽과 잡는 쪽이 **같은 함수**를 봅니다. 둘이 따로 계산하면
마지막 줄인데도 바는 중간에 멈춰 있는 것처럼 보입니다.

### 변수 상자의 생김새와 자리

`Entry.Variable` 의 값을 그대로 씁니다 — 이름 `10pt`, 값 `9pt`, 테두리 `#aac5d5` 1px.

```
바깥 상자   rr(0, -14, 이름폭 + 값폭 + 35, 24, 4)
값 상자     rr(이름폭 + 14, -10, 값폭 + 15, 16, 7)
이름 글자   (4, -2)            값 글자  (이름폭 + 21, -2)
리스트 상자 rr(0, 0, 너비 + 7, 높이 + 22, 7)
리스트 한 줄 20 높이, 값 띠 rr(18, 4, …, 17, 2), 번호·값 모두 y = 12.5
리스트 제목 y = 11.5 (제목 띠 23 의 한가운데)
```

**글자는 세로 가운데를 기준으로 답니다**(`anchor.y = 0.5`). 엔트리의 WebGL 경로는
`GL_VAR_POS`·`GL_LIST_POS` 의 y 를 글자의 윗변으로 쓰지만(`PIXIHelper.text` 가 anchor 를
건드리지 않습니다), 윗변을 맞추면 글꼴의 어센트·디센트만큼 글자가 상자 안에서 아래로
처집니다. 위 표의 y 는 그래서 **상자의 세로 한가운데 선**입니다 — 값 상자는 -14~10 이라
-2, 리스트 한 줄의 값 띠는 4~21 이라 12.5. 글꼴이 바뀌어도 가운데가 유지됩니다.

자리는 작품이 들고 있는 변수의 `x`·`y` 입니다. 대답과 초시계도 변수라 마찬가지고, 둘 다
0 이면 엔트리의 기본 자리(대답 `150,-100` · 초시계 `240 - (이름 길이 × 12 + 70), -70`)로
갑니다. 일반 변수는 `10 - 240 + …` 격자입니다.

**상자는 달라졌을 때만 다시 그립니다.** 모든 모니터가 매 프레임 그려지는데, 값이 그대로인
상자를 다시 만들면 글자 재기와 지오메트리를 매번 새로 합니다. 값 상자는 `이름·값·색` 이
같으면 자리만 옮기고 넘어가고, 리스트 상자는 틀(`이름·너비·높이·첫 줄·넘침`)과 줄
(`번호·값`)을 따로 봅니다. 리스트의 줄은 매 프레임 만들었다 버리지 않고 자리마다 하나씩
두고 글자만 고쳐 씁니다 — `Text` 를 만드는 일은 글자를 재고 텍스처를 굽는 일입니다.
줄이 줄어들면 남는 줄은 지우지 않고 감춥니다.

### 색은 읽지 못해도 오류가 아니다

`Entry.hex2rgb` 는 값을 이렇게 다룹니다.

```
#      을 앞에 붙이고
#abc   는 #aabbcc 로 늘리고
그 밖에 #rrggbb 가 아닌 것은 전부 #000000
```

**읽지 못하는 색은 검정입니다.** 작품은 `#검정` 같은 이름이나 자리를 하나 잃은
16진수를 실제로 들고 다니고, 엔트리는 그것을 검정으로 칠하고 계속 갑니다.

- **붓**(`set_color`·`set_fill_color`)은 엔트리와 같이 `hex2rgb` 를 거친 값을
  들고 있습니다(`cast.hexColor`). 적힌 글자가 아니라 그려질 색입니다.
- **글상자**(`text_change_font_color`·`text_change_bg_color`)는 엔트리와 같이 `#` 만
  붙여 적힌 그대로 들고 있습니다. 엔트리는 그 값을 캔버스에 그냥 넘기고, 캔버스는
  읽지 못하는 색을 무시하고 있던 색을 그대로 둡니다.

pixi 는 무시하는 대신 **던집니다.** 프레임 한가운데서 던지면 `Vm.fail` 이 작품을
통째로 멈추므로(12장 끝), 렌더러는 작품이 준 색을 pixi 에 넘기기 전에
`usableColor` 로 한 번 거릅니다 — 읽히면 그 색, 아니면 글자는 있던 색 그대로,
붓은 검정입니다. 판정 결과는 글자 그대로 기억해 두므로 같은 색을 두 번 재지 않습니다.

한 가지 더: `flush` 는 오브젝트 하나를 그리다 던져도 그 오브젝트만 건너뛰고 나머지를
그립니다. 콘솔에는 그 오브젝트마다 한 번만 남깁니다. 남의 작품을 돌리는 실행기가
값 하나 때문에 통째로 멎으면 안 됩니다.

소스에 적는 색 리터럴(`#efeff`)의 정규화는 이것과 다른 이야기입니다 — 그쪽은 사람이
적는 편의라 여섯 자리에 맞춰 채우고, 실행 중에 흘러드는 값은 엔트리 규칙 그대로입니다
(AI_GRAMMAR.md 8.1).

### 공유 · 실시간 변수는 실행을 넘어 남는다

`shared`(엔트리의 `isCloud`)·`realtime` 변수와 리스트는 엔트리에서 서버에 있습니다.
값이 실행보다 오래 살고, 그 작품을 여는 사람 모두가 같은 값을 봅니다. 사이트 밖에는
서버가 없으므로 브라우저의 저장소가 그 자리를 대신합니다.

- `Variable` 이 `isCloud`·`isRealTime` 을 들고 있고, `loadSnapshot` 은 그런 변수의 값을
  **되돌리지 않습니다**. 시작할 때마다 선언값으로 돌아가면 값을 바꿔도 남지 않아 아무것도
  저장되지 않고 아무것도 고쳐지지 않는 것처럼 보입니다.
- `VariableStore`(`읽기`·`쓰기` 두 가지)를 `Vm` 에 넘기면 작품을 적재할 때 저장된 값을
  덮어 읽고, 실행 중에는 1초마다·멈출 때는 그 자리에서 달라진 것만 씁니다. 저장소를
  넘기지 않으면 실행기가 살아 있는 동안만 값이 이어집니다.
- 브라우저 쪽 구현은 `src/web/store.ts` 로, `tessvm:vars:<작품>:<변수 id>` 키의
  localStorage 입니다. 작품 이름은 `project.id` 가 있으면 그것, 없으면 작품 이름입니다.
  사생활 보호 창처럼 저장소를 막은 곳에서는 `null` 을 돌려주고 메모리에만 남습니다.

컴파일이 결정적(소스에서 씨앗을 뽑습니다)이라 변수 id 가 실행마다 같고, 그래서 키가
흔들리지 않습니다.

**저장소는 서버가 없는 곳에서만 씁니다.** playentry 에서는 그 값이 사이트의 것이므로
확장은 `store: null` 로 띄웁니다(AI_EXTENSION.md 3장). 엔트리에서도 `isCloud` 변수는
읽고 쓰는 것이 전부 그 자리(`value_`·`array_`)이고, 작품과 함께 저장될 뿐 보는 사람이
바꾼 값이 서버로 가지는 않습니다 — 여기서 따로 담아 두면 그 사람에게만 보이는 값이
생깁니다.

`isRealTime` 은 다릅니다. 엔트리는 읽기도 쓰기도 전부 `cloudVariable` 을 거쳐
소켓(`socket.io`, `path: '/cv'`)으로 서버에 묻습니다. 그 서버 주소와 접속 토큰은
entryjs 가 아니라 playentry 쪽이 `setServerInfo` 로 넘겨 주는 값이라 이 저장소에는
없습니다. 지금 확장은 엔트리가 그 소켓에 붙지 못했을 때와 같은 자리(`connect_error`
분기 — 작품이 들고 온 값으로 그 자리에서 돕니다)에 있습니다.

### 프레임 안에서 난 예외는 실행을 멈추고 알린다

스크립트에서 난 예외는 그 스레드만 끝내고 `onError` 로 알립니다(`runThread`). 그 바깥 —
렌더러, 충돌 저장소, 잃어버린 webgl 컨텍스트 — 에서 난 것은 `advance` 를 뚫고 나갔습니다.
프레임 드라이버는 **다음 프레임을 먼저 예약해 두고** 콜백을 부르므로 루프가 멈추지도
않아서, 마지막에 그린 화면 그대로 굳은 채 매 프레임 같은 예외를 다시 던지고, 왜 그런지는
아무 데도 나오지 않았습니다.

`advance` 가 틱 루프와 `flush` 를 감싸고, 잡은 것은 `Vm.fail` 이 처리합니다 — 스크립트
오류와 같은 통로(`errors`·`onError`)로 알리고 실행을 멈춥니다. 한 프레임을 끝내지 못한
것이라 이어서 돌릴 것이 없기 때문입니다. 메시지만으로는 어디서 났는지 알기 어려워
스택은 콘솔에 남깁니다. `boot` 의 `step` 에도 같은 그물이 하나 더 있습니다.

## 13. 번들 단계가 없다

브라우저 쪽 코드도 `.ts` 그대로 두고, 서버가 내보낼 때 `stripTypeScriptTypes` 로 **타입만
지웁니다**. 타입은 공백으로 바뀌므로 줄과 열이 저장소와 같고, 개발자 도구에서 본 위치가
곧 파일의 위치입니다. `pixi.js` 는 임포트 맵으로 잇습니다.

```html
<script type="importmap">{"imports": {"pixi.js": "/vm/pixi.mjs"}}</script>
<script type="module">import { boot } from '/vm/web/boot.ts';</script>
```

이 때문에 브라우저용 파일에는 **지울 수 있는 문법만** 쓸 수 있습니다(`erasableSyntaxOnly`
— `enum`·`namespace`·생성자 매개변수 프로퍼티 금지). 저장소 전체가 이미 그 규칙이라
새로 지킬 것은 없습니다.

타입 검사는 두 벌입니다. 노드 쪽은 루트 `tsconfig.json`, 브라우저 쪽은
`packages/tessvm/tsconfig.browser.json`(`lib: dom`). 그래서 **DOM 타입이 노드 쪽으로
새지 않도록** 캔버스가 필요한 부분만 따로 뒀습니다 — `collision/mask.ts` 는 순수한 자료
구조이고 `collision/mask-image.ts` 만 캔버스를 씁니다. VM 은 `MaskStore` 에 "키를 주면
마스크를 돌려주는 함수" 를 받으므로, 브라우저에서는 렌더러가 그림에서 만들고 테스트에서는
직접 만들어 넣습니다.

## 14. 헤드리스 실행

렌더러와 소리를 `null` 로 두면 VM 만 돕니다. `tessvm bench` 와 테스트가 이 모드를 씁니다.

```ts
const vm = new Vm({ renderer: null, audio: null });
vm.load(project);
vm.start();
for (let i = 0; i < 600; i++) vm.tick();   // 10초치
```

실측(이 저장소의 예제, 노드 24, 화면 없음):

| 작품                   | 오브젝트 | 컴파일  | 틱당      |
| ---------------------- | -------- | ------- | --------- |
| `boss.ent`             | 139      | ~23 ms  | 0.003 ms  |
| `deltarune.ent`        | 136      | ~101 ms | 0.012 ms  |
| `witch.ent`            | 559      | ~68 ms  | 0.004 ms  |

브라우저에서 `deltarune.ent` 를 **그리기까지 포함해** 재면 프레임당 0.18 ms 정도입니다
(60fps 예산 16.7 ms 의 1%). 컴파일 시간은 작품을 열 때 한 번만 듭니다.

## 15. 엔트리와 나란히 돌려 맞춰 본 방법

"엔트리와 똑같이" 를 눈으로 확인하는 것은 믿을 게 못 됩니다. 그래서 **같은 작품을 두
실행기에서 프레임 단위로 돌리고 상태를 해시로 비교**했습니다.

같은 저장소에 실제 엔트리 실행기를 띄우는 `tess run` 이 있으므로, `.ent` 를 되돌린
소스를 양쪽에 물리면 됩니다.

```bash
tessvm run examples/ent/deltarune.ent --keep temp/dr_tess --port 2014   # tessvm
tess   run temp/dr_tess/main.tess                --port 2015            # 진짜 엔트리
```

엔트리를 프레임 단위로 세우려면 브라우저 콘솔에서 세 가지를 붙잡아야 합니다.

1. `clearInterval(Entry.engine.ticker)` 로 자기 타이머를 끄고 `Entry.engine.update()` 를
   직접 부릅니다.
2. `Entry.TimeWaitManager` 와 `Entry.engine.setTimeout` 을 **프레임 카운터**로 바꿔 낍니다.
   원래는 실시간 `setTimeout` 이라 수동 스텝과 어긋납니다.
3. `Date` 를 가짜로 바꿔 프레임마다 `1000/FPS` 씩 흐르게 합니다. 초시계가 실시간을 보기
   때문인데, 로직을 건드리지 않고 **시간 출처만** 바꾸는 것이 요령입니다.

그다음 양쪽에서 `[id, x, y, 회전, 이동방향, 배율x, 배율y, 보이기, 투명도, 모양이름,
복제본수]` 를 줄로 만들어 해시를 비교합니다.

결과 — `deltarune.ent`(오브젝트 136, `speed: 29`)를 100프레임 간격으로 800프레임까지,
그리고 키 입력을 섞어 장면을 두 번 넘길 때까지 **모든 검사점에서 해시가 같았습니다**.
복제본 96개의 좌표와 글상자가 잰 크기까지 포함해서입니다.

이 비교로 실제로 찾아 고친 것들입니다.

| 증상                                        | 원인                                                       |
| ------------------------------------------- | ---------------------------------------------------------- |
| 작품이 두 배 빨리 돌았다                    | `project.speed`(29)를 무시하고 60으로 돌리고 있었다        |
| 메뉴 글자가 왼쪽으로 잘렸다                 | 글상자 정렬을 글자 위치로 처리했다 (기준점이어야 한다)     |
| 글꼴이 대체 글꼴로 나왔다                   | 글꼴 문자열을 정규식으로 잘라 소수점 크기를 못 읽었다      |
| 글상자에서 잰 크기가 엔트리와 달랐다        | 대체 글꼴 목록 때문에 줄 높이가 달라졌고, 재는 시점이 한 프레임 늦었다 |
| 큰 작품이 아예 안 떴다                      | 그림 2천 장을 한꺼번에 요청했다                            |
| 화면에 빨간 `ERROR!` 가 뜨고 얼굴이 안 나왔다 | `모양을 2로 바꾸기` 처럼 **번호로 고르는 모양**을 못 찾아 첫 모양으로 떨어졌다 |
| 가구가 대화상자 위에 그려졌다               | 복제본을 오브젝트별 층에 몰아 그렸다 — 엔트리는 복제본마다 제 깊이가 있다 |

## 16. 디버거 — 엔트리 쪽과 같은 패널을 쓴다

실행 페이지 오른쪽 위 **디버그** 단추로 여는 패널은 `@tess/player` 의 `debug-ui.ts`
**그 파일 그대로**입니다. 서버가 `/debug-ui.js` 와 `/preact/…` 를 엔트리 실행기 쪽과 같은
주소로 내보내고, 페이지는 같은 껍데기(`#debug-panel`·`#debug-toggle`)와 같은 스타일
(`DEBUG_PANEL_STYLE`)을 답니다.

패널은 실행기를 **어댑터 하나로만** 만납니다.

```js
// packages/player/src/debug-ui.ts
const rt = () => window.tessRuntime ?? entryRuntime;
```

`entryRuntime` 은 `window.Entry` 를 쓰는 기본 구현이고, tessvm 은 실행 페이지에서
`makeVmRuntime(handle)` 이 만든 어댑터를 `window.tessRuntime` 에 걸어 둡니다. 패널 코드에는
실행기 이름이 남아 있지 않고, 두 실행기가 갈라지는 곳은 이 어댑터뿐입니다.

| 패널이 하는 일        | tessvm 어댑터가 하는 일                                       |
| --------------------- | ------------------------------------------------------------- |
| 시작 · 일시정지 · 정지 | `vm.start()` · `vm.pause()` · `stop` 은 정지 뒤 되돌리기까지    |
| 변수 · 리스트 보기/고치기 | `vm.variables` 를 엔트리 API 모양으로 감싼다 (`getValue`·`replaceValue` …) |
| 신호 보내기           | `vm.fireEvent('when_message_cast', id)`                        |
| 오브젝트 정보 · 고치기 | `vm.targetOf(id)` — `Entity` 가 이미 엔트리와 같은 이름을 씁니다 |
| 장면 바로가기         | 실행을 켠 뒤 `selectScene` → `fireEvent('when_scene_start')`   |
| 실행 환경 흉내내기    | `vm.boost`·`vm.touch`·`vm.deviceType`·`vm.user`·`vm.maskUserId` 에 곧바로 넣는다 |
| 무대에서 오브젝트 고르기 | 지금 장면의 오브젝트를 앞에서부터 (`vm.currentTargets()`), 모양의 픽셀로 판정 (`hitTest` → `collision.touchingMouse`) |

**환경 흉내내기가 실행기마다 다릅니다.** 엔트리는 판단 블록의 `func` 을 감싸야 하지만
(브라우저에 직접 묻기 때문입니다), tessvm 은 그 답을 VM 이 필드로 들고 있어서 값을 그냥
넣습니다. 그래서 패널은 값을 고를 때마다 `patchEnvironment(state.env)` 를 다시 부릅니다 —
감싸는 쪽에서는 두 번째부터 아무 일도 하지 않습니다.

**아이디·닉네임도 이 자리에서 바꿉니다.** 엔트리는 `window.user` 를 읽으므로 패널이
`get_user_name`·`get_nickname` 의 `func` 을 감싸고, tessvm 은 `vm.user` 를 들고 있어서
그대로 넣습니다. 아이디 칸과 닉네임 칸이 둘 다 비어 있으면 실행기가 시작할 때 받은 값을
쓰고, 그것도 없으면 두 블록이 `guest` 를 돌려줍니다. '아이디 가리기' 는 아이디의 앞 두
글자만 남깁니다(`ddtt786` → `dd*****`) — 닉네임에는 걸리지 않습니다. 확장은 이 값을
playentry 의 `__NEXT_DATA__` 에서 읽어 넘깁니다(AI_EXTENSION.md).

**오류는 VM 에서 곧장 옵니다.** `vm.onError` 로 받은 오류를 소스맵(`/sourcemap.json`)으로
`.tess` 줄·열까지 찾아 오류 탭에 쌓고, 그 블록을 블록 트리에서 강조합니다. 같은 블록에서
같은 오류가 계속 나도 한 번만 알립니다. 터미널에도 같은 내용이 찍힙니다(`/__log`).

`test/tessvm-debug.test.ts` 가 이 조합을 그대로 확인합니다 — 브라우저에 나가는 그 패널
파일을 jsdom 에 올리고, 실행기 자리에 `makeVmRuntime` 을 놓은 채 탭을 눌러 봅니다.

## 17. 남의 작품은 믿지 않는다

`.ent` 는 인터넷에서 받아 오는 남의 파일이고, 그 안의 글자는 전부 작성자가 정합니다.
그 글자가 **코드가 되는 자리**가 셋 있어서, 모두 한 겹씩 막아 두었습니다.

| 자리                     | 무엇이 되나                                   | 막는 것                                |
| ------------------------ | --------------------------------------------- | -------------------------------------- |
| JIT 가 만드는 자바스크립트 | 블록 이름이 `/* … */` 주석에 그대로 들어갔다 | `codegen.ts` 의 `comment()`            |
| 되돌린 `.tess` 소스      | 이름·메모가 `#` 주석과 문자열을 끊었다        | `ident.ts` 의 `tessComment`·`tessString` |
| 디스크에 쓰는 파일       | `imageType`·`ext` 가 경로를 거슬러 올라갔다   | `safeExt()` 와 `load.ts` 의 울타리     |

**블록 이름은 주석을 닫고 나올 수 있었습니다.** 알 수 없는 블록은 `/* 이름 */` 으로
남는데, 이름이 `*/;코드;/*` 이면 그 자리가 남의 코드가 되고 프로그램 전체가
`new Function` 을 지납니다. 확장에서는 그것이 playentry.org 출처에서 도는 코드입니다.
이제 이름에서 낱말 글자·`.`·`-` 만 남기고 60자에서 자릅니다 — 엔트리의 블록 이름은
원래 그 범위 안이라 잃는 것이 없습니다.

**주석과 문자열은 한 줄을 벗어날 수 있었습니다.** 렉서가 줄의 끝으로 치는 글자는
`\n`·`\r`·`\u2028`·`\u2029` 넷인데, 되돌리기는 앞의 둘만 다뤘습니다. 오브젝트 이름에
`\u2028` 하나만 있어도 문자열 리터럴이 닫히지 않아 되돌린 소스가 아예 읽히지 않았고,
블록 이름의 줄바꿈은 `#` 주석을 끊고 그 뒤를 문장으로 만들었습니다.

**모양 파일은 폴더 밖에 쓰일 수 있었습니다.** 저장 경로의 확장자를 `imageType`·`ext` 에서
그대로 가져와서, `png/../../../../evil` 이면 내보낼 폴더 위로 올라갔습니다. 확장자는
이제 영숫자 8자까지만 남기고, 파일을 쓰는 `load.ts` 도 폴더 밖 경로를 거부합니다.

확장 쪽은 `fileurl` 을 믿지 않습니다 — 작품 데이터에 들어 있는 값이라 작성자가 아무 데나
겨눌 수 있고, 남의 호스트면 읽는 사람의 브라우저가 그리로 요청을 보냅니다. 같은 출처일
때만 그대로 쓰고 아니면 `filename` 으로 다시 만듭니다(AI_EXTENSION.md).

`test/security.test.ts` 가 이 셋을 그대로 두드려 봅니다.

## 18. 지금 하지 못하는 것


`tessvm check <파일>` 이 그 작품에서 못 도는 블록을 세어 줍니다. 종류로 나누면 이렇습니다.

- **확장 블록** — 날씨·축제·재난문자·국민행동요령(12종). playentry.org 의 서버에서 자료를
  받아 오는 블록이라 그 API 없이는 값을 만들 수 없습니다. 지금은 값을 돌려주지 않고
  (`undefined`) 실행은 계속합니다.
- **인공지능·하드웨어 블록** — 오브젝트 인식·번역·음성 인식·모델 학습, 각종 로봇.
- **표 저장하기** — 만들기 화면이 있어야 하는 블록이라 실행 중에는 아무 일도 하지
  않습니다. `표 보이기`·`차트 보이기`는 창을 띄우고, 표를 **읽고 고치는** 블록(행·열
  추가, 값 읽기/쓰기, 합계·평균·표준편차·상관계수·조회)도 전부 동작합니다.
- **읽어주기(TTS)** 는 브라우저의 음성 합성으로 대신합니다. 엔트리는 playentry.org 가 만든
  mp3 를 받아 재생하므로 목소리가 다릅니다. 대신 인터넷 없이 동작합니다.
- **표 저장하기**와 확장 블록 말고는, 알려진 미구현은 없습니다.

## 19. 판단이 필요했던 지점

**`부스트 모드인가?` 는 기본이 참입니다.** 엔트리에서 부스트 모드는 2D 와 WebGL 중
무엇으로 그릴지 고르는 스위치인데, tessvm 에는 WebGL 하나뿐이라 이 블록이 돌려주는
값이 전부입니다. 그래서 켜고 끌 것이 없이 참으로 둡니다 — 부스트를 요구하는 작품
(`badapple.ent` 는 아니면 "부스트모드를 켜주세요" 장면으로 넘어갑니다)이 그냥 돕니다.
같은 이유로 디버그 패널도 **지금 켜졌는지 꺼졌는지 알리지 않습니다**. 알릴 현재 값이
없기 때문입니다(어댑터의 `realBoost` 가 `null` 을 돌려주고, 패널은 그 자리에 렌더러가
늘 WebGL 이라는 설명만 둡니다). 흉내내기로 이 블록의 답만 거짓으로 바꿀 수는 있습니다.

**제너레이터를 돌고 있는 중에 닫지 않습니다.** `자신의 다른 코드 멈추기`·장면 넘기기는
자기 자신을 멈출 수 있는데, 실행 중인 제너레이터에 `.return()` 을 부르면
`Generator is already running` 으로 터집니다. `Thread.stop` 은 실행 중이면 `done` 만
세우고 돌아갑니다 — 그 프레임은 코드가 알아서 끝납니다.

**모르는 블록에서 멈추지 않습니다.** 확장 블록 하나 때문에 작품 전체가 안 도는 것보다,
그 블록만 건너뛰고 나머지를 보여 주는 쪽이 낫습니다. 대신 `check` 로 정확히 무엇이
빠졌는지 셀 수 있게 했습니다. (컴파일러의 '느슨한 실행' 과 같은 태도입니다.)

**틱은 고정 60Hz 누적기로 돕니다.** 엔트리는 `setInterval(1000/60 을 내림한 16ms)` 라
실제로는 초당 62.5번 돕니다. tessvm 은 `requestAnimationFrame` 으로 화면을 맞추되 틱은
정확히 초당 60번 돌리고, 한 프레임에 밀린 틱은 최대 4번까지만 따라잡습니다(그 이상 밀리면
따라잡느라 더 밀리는 악순환이 됩니다).

**`change_variable` 은 문자열을 저장합니다.** 엔트리가
`new BigNumber(a).plus(b).toNumber().toFixed(자릿수)` 를 그대로 넣기 때문입니다. 값을
숫자로 바꿔 담으면 `문자/숫자인가?` 판단과 이어 붙이기 결과가 달라집니다.
