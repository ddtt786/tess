# 07. 디버깅과 에러

문법을 작성하다 보면 "왜 이 입력이 매칭이 안 되지?" 하는 순간이 반드시 옵니다. 이번 문서에서는 Ohm이 제공하는 디버깅 도구와, 자주 마주치는 에러 메시지들을 정리합니다.

## 방법 1: 온라인 에디터(시각화 도구)

가장 직관적인 방법은 [Ohm 온라인 에디터](https://ohmjs.org/editor)를 사용하는 것입니다. 왼쪽에 문법, 오른쪽에 입력을 넣으면 파스 트리가 실시간으로 시각화되어서, 어느 규칙에서 어떻게 매칭(혹은 실패)되는지 한눈에 볼 수 있습니다. 새 문법을 실험하거나 복잡한 규칙을 디버깅할 때 항상 열어두는 걸 추천합니다.

## 방법 2: 텍스트 트레이스 — `trace()`

코드 안에서 바로 확인하고 싶다면 `match()` 대신 `trace()`를 씁니다. 인자는 `match()`와 동일하지만, 결과로 `Trace` 객체를 반환합니다. `.toString()`을 호출하면 파서가 내린 모든 결정을 요약한 문자열을 얻을 수 있습니다.

```js
const g = ohm.grammar('G { start = letter+ }');
console.log(g.trace('ab').toString());
```

출력 예시:

```
ab         ✓ start ⇒  "ab"
ab           ✓ letter+ ⇒  "ab"
ab             ✓ letter ⇒  "a"
ab                 ✓ lower ⇒  "a"
ab                   ✓ Unicode [Ll] character ⇒  "a"
b              ✓ letter ⇒  "b"
b                  ✓ lower ⇒  "b"
b                    ✓ Unicode [Ll] character ⇒  "b"
               ✗ letter
                   ✗ lower
                     ✗ Unicode [Ll] character
                   ✗ upper
                     ✗ Unicode [Lu] character
                   ✗ unicodeLtmo
                     ✗ Unicode [Ltmo] character
           ✓ end ⇒  ""
```

읽는 법:

- 각 줄의 맨 앞은 그 시점에 남아있는 입력
- `✓`는 그 규칙이 성공, `✗`는 실패했다는 표시
- 들여쓰기가 깊어질수록 더 안쪽 규칙(하위 규칙)을 의미
- `⇒ "값"`은 그 규칙이 실제로 매칭해서 소비한 문자열

이렇게 보면 `letter+`가 `'a'`, `'b'`를 차례로 소비하다가 세 번째 시도에서 `letter`가 실패했고(더 이상 글자가 없으므로), 그래서 반복을 멈추고 `end` 규칙으로 넘어가 성공했다는 흐름을 알 수 있습니다.

## 매칭 실패 시 에러 메시지 활용하기

문법 자체가 아니라 **입력**이 잘못된 경우([04번 문서](./04-실전-예제-계산기-만들기.md) 참고), `MatchResult`의 `message`를 확인하면 어디서 왜 실패했는지 알 수 있습니다.

```js
const bad = g.match('2 +');
console.log(bad.message);
```

## 문법 자체가 잘못됐을 때 나오는 에러들

아래는 **문법을 정의(인스턴스화)하는 단계**에서 발생할 수 있는 에러 종류입니다. 즉 `ohm.grammar(...)`를 호출할 때 던져지는 에러들입니다.

### `GrammarSyntaxError` — 문법 자체의 문법 오류

Ohm 언어의 문법 규칙을 어긴 경우입니다.

```
Uncaught ohm.error.GrammarSyntaxError: Failed to parse grammar:
Line 5, col 11:
  4 | G {
> 5 |   start = *x
                ^
  6 | }
Expected "~", "&", "#", an identifier, "\"", a number, "(", "[", "`", "{", "--", "|", or "}"
```

→ [02-Ohm-문법-가이드.md](./02-Ohm-문법-가이드.md)를 참고해서 문법 요소를 다시 확인해보세요. 위 예시는 `*`가 표현식 없이 단독으로 쓰여서 발생한 오류입니다(`*`는 반드시 어떤 표현식 뒤에 붙어야 함).

### `UndeclaredGrammar` — 존재하지 않는 문법을 참조

```
Uncaught ohm.error.UndeclaredGrammar: Grammar Foo is not declared in namespace [object Object]
```

→ 다른 문법을 상속(`<:`)하는데, 그 상위 문법을 Ohm이 찾지 못한 경우입니다. 해결 방법:

- 여러 문법을 한 번에 정의한다면, 상위 문법이 **먼저** 나오도록 순서를 맞추세요.
- 상위 문법이 다른 곳에서 정의되어 있다면, `ohm.grammar()` 호출 시 두 번째 인자로 네임스페이스 객체를 넘겨줘야 합니다.

```js
const ns = {};
ns.G1 = ohm.grammar('G1 {}');
const g2 = ohm.grammar('G2 <: G1 {}', ns);
```

### `DuplicateGrammarDeclaration` — 문법 이름 중복

```
Uncaught ohm.error.DuplicateGrammarDeclaration: Grammar G is already declared in namespace [object Object]
```

→ 같은 네임스페이스 안에 같은 이름의 문법이 이미 있는 경우입니다. 같은 문법을 실수로 두 번 인스턴스화하지 않았는지, 혹은 다른 네임스페이스를 써야 하지 않는지 확인하세요.

### `UndeclaredRule` — 존재하지 않는 규칙 참조

```
Uncaught ohm.error.UndeclaredRule: Rule lettr is not declared in grammar G
```

→ 규칙 본문에서 정의되지 않은 다른 규칙을 호출한 경우입니다. 보통은 오타입니다(`lettr` → `letter`).

### `CannotOverrideUndeclaredRule` — 없는 규칙을 `:=`로 덮어쓰려 함

```
Uncaught ohm.error.CannotOverrideUndeclaredRule: Cannot override rule foo because it is not declared in BuiltInRules
```

→ `:=`(덮어쓰기)를 쓰려면 상위 문법에 같은 이름의 규칙이 이미 있어야 합니다. 없다면 그냥 `=`(새로 정의)를 쓰세요.

### `CannotExtendUndeclaredRule` — 없는 규칙을 `+=`로 확장하려 함

```
Uncaught ohm.error.CannotExtendUndeclaredRule: Cannot extend rule start foo it is not declared in BuiltInRules
```

→ `+=`(확장)도 마찬가지로 상위 문법에 규칙이 먼저 있어야 합니다.

### `DuplicateRuleDeclaration` — 같은 이름의 규칙을 또 정의

```
Uncaught ohm.error.DuplicateRuleDeclaration: Duplicate declaration for rule 'letter' in grammar 'G' (originally declared in grammar 'BuiltInRules')
```

→ 이미 있는 규칙(자기 문법이든, 내장 규칙이든, 상위 문법이든)을 `=`로 또 정의하려 한 경우입니다. 이미 있는 규칙을 바꾸고 싶다면 `:=`(덮어쓰기)나 `+=`(확장)를 사용하세요.

## 정리 — 문제 해결 체크리스트

| 증상 | 확인할 것 |
|---|---|
| 문법을 만들 때부터(`ohm.grammar()`) 에러가 남 | 이 문서의 에러 종류표 확인, [02번 문서](./02-Ohm-문법-가이드.md)로 문법 재점검 |
| 문법은 잘 만들어졌는데 특정 입력만 실패함 | `g.trace(입력)`으로 어느 규칙에서 막히는지 확인 |
| 왜 이렇게 파싱됐는지(우선순위 등) 헷갈림 | 온라인 에디터로 파스 트리를 시각적으로 확인 |
| 시맨틱 액션에서 "missing semantic action" 에러 | [03번 문서](./03-시맨틱-액션과-오퍼레이션.md)의 `_iter`/`_nonterminal`/`_terminal` 설명 확인 |
