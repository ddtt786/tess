# 02. Ohm 문법 가이드

이 문서는 Ohm의 문법 언어(Ohm language) 자체의 문법을 다룹니다. Ohm은 PEG(Parsing Expression Grammar)를 기반으로 하지만, 몇 가지 독자적인 특징이 있습니다.

- 규칙 이름의 **대소문자가 의미를 가짐** (뒤에서 설명)
- 문법은 오직 "이 입력이 맞는가"만 판단하고, 실제 동작(시맨틱 액션)은 완전히 분리되어 있음
- 선택(alternation) 표현식에 이름(case name)을 붙일 수 있음

## 용어 정리

```
Arithmetic {
  Expr = "1 + 1"
}
```

- 이 전체가 **문법(grammar)** 이며, 이름은 `Arithmetic`
- `Expr`은 **규칙(rule)** 이름
- `= "1 + 1"` 부분이 **규칙 본문(rule body)**
- 규칙 본문에 올 수 있는 모든 표현을 **파싱 표현식(parsing expression)** 이라고 부릅니다

아래부터는 파싱 표현식의 종류를 하나씩 살펴봅니다.

## 1. 터미널(Terminal) — 문자 그대로 매칭

```
"hello there"
```

큰따옴표 안의 문자와 정확히 일치하는지 검사합니다.

특수문자(`"`, `\`, `'`)는 백슬래시로 이스케이프할 수 있습니다. 예를 들어 `"\""`는 입력 문자열에서 큰따옴표(`"`) 한 글자와 매칭됩니다. 그 외에도 `\b`(백스페이스), `\f`(폼피드), `\n`(줄바꿈), `\r`(캐리지리턴), `\t`(탭), `\xNN`(2자리 16진수 코드), `\uNNNN`(4자리 16진수 코드) 이스케이프를 쓸 수 있습니다.

`\u{16진수}` 형태를 쓰면 0xFFFF보다 큰 유니코드 코드포인트(예: 이모지)도 표현할 수 있습니다. 예: `"\u{1F639}"`는 `'😹'`와 매칭됩니다.

## 2. 터미널 범위(Terminal Range) — 문자 구간 매칭

```
start..end
```

*start*부터 *end* 사이(양 끝 포함)의 코드포인트 하나와 매칭됩니다. 예를 들어 `"a".."c"`는 `'a'`, `'b'`, `'c'` 중 하나와 매칭됩니다.

## 3. 규칙 적용(Rule Application) — 다른 규칙 불러오기

```
ruleName
```

`ruleName`이라는 규칙의 본문을 그대로 매칭 시도합니다. 예를 들어 내장 규칙 `letter`는 알파벳 한 글자를 매칭합니다.

```
ruleName<expr>
```

**매개변수화된 규칙(parameterized rule)** 을 호출하는 방식입니다. `expr`을 첫 번째 매개변수로 넘깁니다. 매개변수가 여러 개면 쉼표로 구분합니다. 예: `ListOf<field, ";">`.

## 4. 반복 연산자: `*`, `+`, `?`

```
expr *
```
`expr`을 0번 이상 반복 매칭합니다. 예: `"a"*`는 `''`, `'a'`, `'aa'` 등과 매칭됩니다.

```
expr +
```
`expr`을 1번 이상 반복 매칭합니다. 예: `letter+`는 `'x'`, `'xA'` 등과 매칭됩니다.

```
expr ?
```
`expr`을 매칭 시도하되, 매칭되든 안 되든 항상 성공합니다(선택적 매칭). 매칭에 실패해도 입력을 소비하지 않습니다.

> 규칙 이름이 **대문자로 시작하는 규칙(syntactic rule)** 안에서는 반복 연산자를 쓸 때 앞에 있는 공백이 자동으로 건너뛰어집니다. 대소문자 규칙의 차이는 아래 "구문 규칙 vs 어휘 규칙"에서 자세히 설명합니다.

## 5. 순차(Sequence) — 순서대로 매칭

```
expr1 expr2
```
`expr1` 다음에 바로 `expr2`가 와야 매칭됩니다. 예: `"grade" letter`는 `'gradeA'`, `'gradeB'` 등과 매칭됩니다.

## 6. 선택(Alternation) — 여러 후보 중 하나

```
expr1 | expr2
```
먼저 `expr1`을 시도하고, 실패하면 `expr2`를 시도합니다. 예: `letter | digit`는 `'a'`나 `'9'` 모두와 매칭됩니다.

> ⚠️ PEG 방식의 특징: 순서대로 시도하다가 **처음 성공하는 것을 선택**합니다. 정규표현식과 달리 "더 긴 것을 우선"하지 않으므로, 후보의 순서가 중요할 수 있습니다.

## 7. 미리보기(Lookahead): `&`

```
& expr
```
`expr`이 매칭될 수 있는지만 확인하고, **입력을 소비하지 않습니다**. 주로 순차식의 일부로 사용합니다. 예: `letter &digit`는 `'a9'`와 매칭되지만 실제로 소비하는 건 `'a'`뿐입니다. `&"a" letter+`는 'a'로 시작하는 글자열만 매칭합니다.

## 8. 부정 미리보기(Negative Lookahead): `~`

```
~ expr
```
`expr`이 매칭되지 **않을 때만** 성공하며, 역시 입력을 소비하지 않습니다. 예: `~"\n" any`는 줄바꿈이 아닌 아무 문자 하나를 소비합니다. 문자열 리터럴, 예약어 처리 등에 자주 쓰입니다.

## 9. 어휘화(Lexification): `#`

```
# expr
```
대문자로 시작하는 규칙(구문 규칙) 안에서 특정 부분만 공백 자동 건너뛰기를 막고 싶을 때 씁니다. 자세한 내용은 아래 "구문 규칙 vs 어휘 규칙" 섹션을 참고하세요.

## 10. 주석

한 줄 주석(`//`)과 여러 줄 주석(`/* */`)을 모두 지원합니다.

```
booleanLiteral = ("true" | "false") // 나중에 "True"/"False"도 지원할지 고민 중

/*
  참고: es5 명세의 Punctuator, DivPunctuator 항목은 이 문법에서 사용하지 않음
*/
```

## 내장 규칙(Built-in Rules)

Ohm은 자주 쓰는 규칙들을 기본으로 제공합니다. `letter`, `digit` 같은 이름은 여러분이 직접 정의하지 않아도 바로 쓸 수 있습니다.

| 규칙 | 설명 |
|---|---|
| `any` | 입력 스트림의 다음 유니코드 문자 하나와 매칭 |
| `letter` | 대소문자 상관없이 알파벳 한 글자 |
| `lower` | 소문자 한 글자 |
| `upper` | 대문자 한 글자 |
| `digit` | 숫자(0~9) 한 글자 |
| `hexDigit` | 숫자 또는 A~F(16진수) 한 글자 |
| `alnum` | 알파벳 또는 숫자 한 글자 (`letter \| digit`와 동일) |
| `space` | 공백 문자(스페이스, 탭, 줄바꿈 등) 한 글자 |
| `end` | 입력의 끝. `~any`와 동일 |
| `caseInsensitive<terminal>` | 대소문자를 구분하지 않고 매칭. 예: `caseInsensitive<"ohm">`은 `'Ohm'`, `'OHM'` 등과 매칭 |
| `ListOf<elem, sep>` | `sep`으로 구분된 `elem`을 0개 이상 매칭. 예: `ListOf<letter, ",">`는 `''`, `'a'`, `'a, b, c'` 등과 매칭 |
| `NonemptyListOf<elem, sep>` | `ListOf`와 같지만 최소 1개 이상 |
| `listOf<elem, sep>` | `ListOf`와 비슷하지만 어휘 규칙(소문자 규칙)으로 취급 |
| `applySyntactic<ruleName>` | 어휘적 문맥(공백 자동 스킵 없는 곳)에서 구문 규칙을 강제로 사용할 때. 앞뒤 공백은 건너뜀 |
| `unicodeChar<categoryOrProp>` | 특정 유니코드 카테고리/속성에 해당하는 문자 하나와 매칭 |

> `any`는 유니코드 코드포인트 기준으로 문자 하나를 매칭합니다(Ohm v17부터). 이모지처럼 2개의 16비트 코드 유닛으로 이루어진 문자도 `any` 하나로 정확히 매칭됩니다.

## 그래머 문법 규칙

### 그래머 상속

```
grammarName <: supergrammarName { ... }
```
`grammarName`이라는 새 문법을 `supergrammarName`을 상속받아 정의합니다. 마치 클래스 상속처럼, 기존 문법의 규칙을 재사용하면서 추가/변경할 수 있습니다.

### 규칙 정의, 확장, 덮어쓰기

셋 다 규칙 이름의 대소문자가 의미를 가진다는 점에 유의하세요(아래 참고).

```
ruleName = expr
```
새 규칙을 정의합니다. 이미 같은 이름의 규칙이 있으면(자기 자신이든 상위 문법이든) 에러가 납니다.

```
ruleName := expr
```
상위 문법(supergrammar)에 있는 같은 이름의 규칙을 **완전히 덮어씁니다**. 상위 문법에 해당 규칙이 없으면 에러가 납니다.

```
ruleName += expr
```
상위 문법의 규칙을 **확장**합니다. 결과적으로 `expr | 기존규칙본문` 형태가 됩니다. 상위 문법에 규칙이 없으면 에러가 납니다.

> `...`(super-splice) 연산자를 쓰면 상위 문법 규칙의 앞/뒤에 케이스를 덧붙일 수 있습니다. 예를 들어 상위 문법에 `comment = multiLineComment`가 있을 때, `comment := ... | singleLineComment`라고 쓰면 `comment := multiLineComment | singleLineComment`와 같아집니다.

### 매개변수화된 규칙

```
ruleName<arg1, ..., argN> = expr
```
`n`개의 매개변수를 갖는 규칙을 정의합니다. 본문 안에서 `arg1` 같은 매개변수 이름을 규칙처럼 사용할 수 있습니다. 예: `Repeat<x> = x x`.

### 규칙 설명(Rule Description)

규칙 이름 뒤에 괄호로 설명을 붙일 수 있습니다. 이 설명은 사용자가 잘못된 입력을 넣었을 때 더 친절한 에러 메시지를 만드는 데 쓰입니다.

```
ident (an identifier)
  = ~keyword name
```

### 인라인 규칙 선언 (`-- caseName`)

```
expr -- caseName
```

파싱 표현식 뒤에 `--`와 이름을 붙이면, 그 부분이 별도의 규칙으로 분리됩니다. 주로 선택(alternation) 표현식에서 각 분기마다 이름을 붙여서, 나중에 시맨틱 액션을 작성하기 쉽게 만들기 위해 사용합니다.

```
AddExp = AddExp "+" MulExp  -- plus
       | MulExp
```

이 코드는 사실 아래 코드와 동일합니다.

```
AddExp = AddExp_plus
       | MulExp
AddExp_plus = AddExp "+" MulExp
```

즉 `-- plus`가 붙은 부분이 `AddExp_plus`라는 별도의 규칙으로 자동 생성되는 것입니다.

## 구문 규칙(Syntactic) vs 어휘 규칙(Lexical)

Ohm에서 정말 중요한 개념입니다.

- **구문 규칙(syntactic rule)**: 규칙 이름이 **대문자**로 시작 (예: `Expr`, `AddExp`)
- **어휘 규칙(lexical rule)**: 규칙 이름이 **소문자**로 시작 (예: `number`, `letter`)

차이는 딱 하나입니다: **구문 규칙은 공백을 자동으로 건너뜁니다.**

"공백"이 무엇인지는 문법의 `space` 규칙이 정의합니다. 기본값은 스페이스, 탭, 줄바꿈, 캐리지리턴 등 흔한 공백 문자입니다.

### 공백 자동 스킵이 실제로 하는 일

구문 규칙의 본문에서는 각 표현식 앞에 자동으로 `spaces`(=`space*`) 규칙이 삽입된다고 생각하면 됩니다. 예를 들어 JSON 문법의 일부를 봅시다.

```
Array = "[" "]"  -- empty
      | "[" Elements "]"  -- nonEmpty
Elements = Element ("," Element)*
```

`Array`, `Elements` 모두 대문자로 시작하므로 구문 규칙입니다. 이걸 공백 스킵을 명시적으로 풀어서 쓰면 아래와 같습니다.

```
array = spaces "[" spaces "]"  -- empty
      | spaces "[" spaces elements spaces "]"  -- nonEmpty
elements = spaces element (spaces "," spaces element)*
```

즉 대문자 규칙을 쓰면 이렇게 지저분한 공백 처리를 직접 안 써도 됩니다.

몇 가지 추가로 알아둘 점:

1. 시작 규칙이 구문 규칙이면, 전체 입력의 맨 앞/맨 뒤 공백도 자동으로 건너뜁니다.
2. 반복 연산자(`+`, `*`)가 있으면 매칭마다 앞의 공백을 건너뜁니다. 즉 `Names = name+`는 `(spaces name)+`와 같습니다.
3. **`#`(어휘화 연산자)** 를 쓰면 구문 규칙 안에서도 특정 부분만 공백 스킵을 막을 수 있습니다.

```
KeyAndValue = #(letter alnum+) ":" #(digit+)
```

이건 아래와 동일합니다.

```
keyAndValue = letter alnum+ spaces ":" digit+
```

`#`로 감싼 부분 안/앞에서는 공백을 건너뛰지 않습니다. 그래서 이 규칙은 `'count :33'`은 매칭하지만 `'count: 33'`은 매칭하지 못합니다. (콜론 앞뒤 공백 규칙이 다르게 처리되기 때문입니다.)

## 정리 표

| 문법 요소 | 문법 | 의미 |
|---|---|---|
| 터미널 | `"abc"` | 문자 그대로 매칭 |
| 범위 | `"a".."z"` | 문자 구간 매칭 |
| 규칙 적용 | `ruleName` | 다른 규칙 호출 |
| 0번 이상 | `expr*` | 반복 |
| 1번 이상 | `expr+` | 반복 |
| 선택적 | `expr?` | 있어도 없어도 됨 |
| 순차 | `expr1 expr2` | 순서대로 |
| 선택 | `expr1 \| expr2` | 둘 중 하나 |
| 긍정 lookahead | `&expr` | 소비 없이 확인 |
| 부정 lookahead | `~expr` | 소비 없이 아닌지 확인 |
| 어휘화 | `#expr` | 공백 스킵 방지 |
| 상속 | `A <: B { }` | 문법 확장 |
| 정의 | `r = expr` | 새 규칙 |
| 덮어쓰기 | `r := expr` | 상위 규칙 교체 |
| 확장 | `r += expr` | 상위 규칙에 케이스 추가 |
| 인라인 규칙 | `expr -- name` | 케이스별 이름 붙이기 |
