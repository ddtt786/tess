# 08. 실전 팁과 주의사항

Ohm 공식 문서의 "Patterns and Pitfalls"에 담긴 내용을 바탕으로, 실제 문법을 작성할 때 자주 부딪히는 문제와 그 해결 패턴을 정리했습니다.

## 문법(Grammar) 관련 팁

### 1. 그리디(greedy) 매칭 다루기

Ohm의 `*`, `+` 같은 반복 연산자는 다른 PEG 도구들처럼 **그리디**합니다. 즉, 가능한 한 최대한 많이 소비합니다. 이게 정규표현식과 다른 점인데, 헷갈리기 쉬우니 예시로 봅시다.

정규표현식 `/^a*a/`는 `'aaa'`와 매칭됩니다(정규식은 실패하면 한 글자씩 양보하면서 재시도하기 때문). 하지만 Ohm에서 `"a"* "a"`는 **절대 매칭되지 않습니다**. `"a"*`가 이미 가능한 모든 `'a'`를 다 먹어버려서, 뒤의 `"a"`가 매칭할 문자가 하나도 안 남기 때문입니다.

해결책은 **부정 lookahead(`~`)** 를 써서 반복이 너무 많이 먹지 않도록 막는 것입니다.

```
allButLastA = (~("a" end) "a")*
```

`"a" end`는 "입력의 맨 끝에 있는 'a'"를 뜻하고, `~("a" end) "a"`는 "그게 마지막 'a'가 아닐 때만 'a' 하나를 매칭"이라는 뜻입니다. 이렇게 하면 마지막 'a'를 제외한 모든 'a'를 매칭할 수 있습니다.

### 2. 구분 문자열(delimited strings) 처리하기

문자열 리터럴이나 주석처럼 "특정 구분자로 둘러싸인 구간"을 매칭할 때도 부정 lookahead가 핵심입니다. 예를 들어 백틱(`` ` ``)으로 감싼 여러 줄 문자열을 지원한다면:

```
stringDelimiter = "`"
string = stringDelimiter (~stringDelimiter any)* stringDelimiter
```

`~stringDelimiter any`는 "닫는 구분자가 아닌 아무 문자 하나"라는 뜻입니다. 이 패턴은 "구분자로 안 끝날 때까지 아무거나 다 먹기"라는 매우 흔한 패턴이니 기억해두면 좋습니다.

### 3. 주석(comment) 지원하기

대부분의 언어에서 주석은 "공백의 한 형태"로 취급됩니다. Ohm의 공백 자동 스킵은 문법의 `space` 규칙을 기준으로 동작하므로([02번 문서](./02-Ohm-문법-가이드.md) 참고), 먼저 주석 규칙을 정의합니다. C 스타일(`/* */`) 주석 예시:

```
comment = "/*" (~"*/" any)* "*/"
```

그리고 이 규칙을 `space` 규칙에 **추가**해줘야 실제로 공백처럼 건너뛰어집니다.

```
space += comment
```

### 4. 예약어(reserved word) / 키워드 처리하기

`if`, `while`, `return` 같은 예약어를 다룰 때는 주의할 점이 두 가지 있습니다.

- 한 예약어가 다른 예약어의 접두어일 수 있습니다. 예: `in`과 `instanceof`.
- 예약어로 **시작하는** 식별자까지 막으면 안 됩니다. 예: `className`이라는 변수명은 허용되어야 합니다(`class`로 시작하지만 예약어가 아님).

두 문제 모두 **부정 lookahead**로 해결합니다.

```
in = "in" ~identifierPart
```

이렇게 하면 (a) `in` 뒤에 식별자 문자가 이어지면(즉 `instanceof`의 일부라면) 매칭되지 않고, (b) `inProgress` 같은 멀쩡한 식별자를 예약어로 잘못 인식하지도 않습니다.

여러 예약어를 한꺼번에 정의할 때는 이렇게 나열합니다.

```
keyword = break    | do        | instanceof | typeof
        | case     | else      | new        | var
        | catch    | finally   | return     | void
        | continue | for       | switch     | while
        | debugger | function  | this       | with
        | default  | if        | throw
        | delete   | in        | try
```

### 5. 정확히 n번 반복 매칭하기

정규표현식의 `{n}` 같은 수량자(quantifier) 문법은 Ohm에 없습니다. 대신 그냥 그 개수만큼 나열합니다.

```
zipCode = digit digit digit digit
```

### 6. 연산자 우선순위 표현하기

[04번 문서](./04-실전-예제-계산기-만들기.md)에서 이미 다뤄본 내용이지만, 원칙을 다시 짚어봅니다. **좌재귀 규칙을 계층적으로 쌓아서** 우선순위를 표현하는 것이 정석입니다.

```
exp = addExp

addExp = addExp "+" mulExp  -- plus
       | addExp "-" mulExp  -- minus
       | mulExp

mulExp = mulExp "*" priExp  -- times
       | mulExp "/" priExp  -- divide
       | priExp
```

낮은 우선순위 연산자(`+`, `-`)의 규칙이 높은 우선순위 연산자(`*`, `/`)의 규칙을 호출하는 구조입니다. 이렇게 하면 `*`, `/`가 "더 강하게 묶이게" 됩니다. 연산자 우선순위/결합법칙에 대한 더 많은 예시는 [Ray Toal의 Operator Precedence and Associativity Examples](https://github.com/ohmjs/ohm/tree/main/examples/operators)를 참고하세요.

> 🐍 **주의: 모호한 재귀**
> `addExp = addExp "+" addExp` 처럼 양쪽 모두에 같은 규칙을 재귀적으로 쓰면 안 됩니다. 이렇게 쓰면 `+`가 왼쪽 결합인지 오른쪽 결합인지 읽는 사람이 알 수 없게 되고, Ohm은 실제로는 오른쪽 결합으로 파싱해버립니다. 항상 "왼쪽엔 자기 자신, 오른쪽엔 한 단계 높은 우선순위 규칙"의 형태를 지키세요.

## 시맨틱(Semantics) 관련 팁

### 반복 노드(iteration node) 다루기

`G { letters = letter+ }`처럼 반복 연산자로 만들어진 값은 **반복 노드**입니다. 이걸 시맨틱 액션에서 다루는 방법은 두 가지입니다.

1. `children` 배열에 `map`, `filter` 같은 배열 메서드를 직접 사용

```js
iterNode.children.map(c => c.prettyPrint());
```

2. 오퍼레이션에 `_iter` 액션을 정의해서 `iterNode.prettyPrint()`처럼 바로 호출할 수 있게 하기 (정의하지 않으면 "missing semantic action" 에러 발생)

### 선택적 노드(optional node) 다루기

`?` 연산자로 만들어진 노드는 자식이 0개 또는 1개인 특수한 반복 노드입니다. 최신 JavaScript/TypeScript의 **옵셔널 체이닝(`?.`)** 을 쓰면 아주 깔끔하게 처리할 수 있습니다.

```js
optNode.child(0)?.myOperation();
```

이렇게 하면 (a) 자식이 없으면 `undefined`, (b) 자식이 있으면 그 자식에 대한 `myOperation()` 결과를 얻습니다. 구버전 JavaScript에서는 `optNode.child(0) && optNode.child(0).myOperation()`처럼 쓰거나, `optNode.children.map(c => c.myOperation())[0]`처럼 쓸 수도 있습니다.

### 내장 리스트 규칙 다루기

`listOf` 같은 내장 리스트 규칙을 문법에서 사용했다면, 보통은 그것을 위한 시맨틱 액션을 따로 작성할 필요가 없습니다. [03번 문서](./03-시맨틱-액션과-오퍼레이션.md)에서 소개한 내장 오퍼레이션 `asIteration()`을 사용하면 됩니다.

## 요약 표

| 상황 | 해결 패턴 |
|---|---|
| 반복이 너무 많이 먹어버림 | 부정 lookahead로 멈출 조건 명시: `(~조건 expr)*` |
| 문자열/주석처럼 구분자로 감싸인 구간 | `구분자 (~구분자 any)* 구분자` |
| 주석을 공백처럼 취급하고 싶음 | `comment` 규칙 정의 + `space += comment` |
| 예약어가 다른 식별자의 접두어가 됨 | `"키워드" ~identifierPart` |
| `{n}`처럼 정확히 n번 반복 | 그냥 n번 나열: `digit digit digit digit` |
| 연산자 우선순위 표현 | 좌재귀 규칙을 우선순위별로 계층화 |
| 반복 노드 처리 | `children.map(...)` 또는 `_iter` 액션 |
| 선택적(`?`) 노드 처리 | `node.child(0)?.연산()` |
| 리스트 규칙(`ListOf` 등) 처리 | `asIteration()` |
