# 03. 시맨틱 액션과 오퍼레이션

앞에서 문법으로 "이 입력이 맞는 형식인가"까지는 확인할 수 있었습니다. 이번 문서에서는 매칭에 성공한 결과를 가지고 **실제로 무언가를 계산하거나 변환**하는 방법을 배웁니다.

## 왜 문법과 동작을 분리했을까?

많은 파서 도구들은 문법 규칙 안에 직접 "이 부분을 매칭하면 이 값을 리턴해라" 같은 코드를 섞어서 씁니다. Ohm은 이렇게 하지 않고, **문법(Grammar)** 과 **시맨틱(Semantics)** 을 완전히 분리합니다.

- 문법: 순수하게 "입력이 유효한가"만 정의
- 시맨틱: "유효한 입력을 어떻게 처리할 것인가"를 정의

이렇게 분리하면 같은 문법에 대해 여러 종류의 처리(예: 계산하기, 예쁘게 출력하기, 타입 검사하기 등)를 독립적으로 여러 개 만들 수 있고, 서로 이름이 겹칠 걱정도 없습니다.

## 핵심 용어 3가지

| 용어 | 설명 |
|---|---|
| **Semantics** | 한 문법에 대한 "동작들의 묶음". 하나의 문법에 여러 개의 Semantics를 만들 수 있음 |
| **Operation** | 매칭 결과 트리를 순회하면서 값을 계산하는 함수. 호출할 때마다 다시 계산됨 |
| **Attribute** | Operation과 같지만, 결과가 **메모이즈(캐싱)** 되어서 같은 노드에 대해 한 번만 계산됨 |

Operation은 마치 [방문자 패턴(Visitor pattern)](https://ko.wikipedia.org/wiki/%EB%B0%A9%EB%AC%B8%EC%9E%90_%ED%8C%A8%ED%84%B4)처럼 동작합니다. 파스 트리(parse tree)를 재귀적으로 순회하면서, 각 노드마다 여러분이 정의한 **액션 딕셔너리(action dictionary)** 안의 해당 함수를 실행합니다.

## Semantics 만들고 Operation 추가하기

```js
const g = ohm.grammar(String.raw`
  Name {
    FullName = name name
    name = (letter | "-" | ".")+
  }
`);

const semantics = g.createSemantics();

semantics.addOperation('prettyPrint', {
  FullName(first, last) {
    return `${first.prettyPrint()} ${last.prettyPrint()}`;
  },
  name(chars) {
    return chars.sourceString;
  }
});

const result = g.match('Jane Doe');
console.log(semantics(result).prettyPrint());
// -> "Jane Doe"
```

흐름을 정리하면:

1. `g.createSemantics()`로 문법에 대한 Semantics 객체 생성
2. `.addOperation(이름, 액션딕셔너리)`로 오퍼레이션 등록
3. `semantics(매칭결과)`로 매칭 결과를 감싸고, `.오퍼레이션이름()`을 호출

Semantics 객체의 주요 메서드는 모두 `this`(체이닝 가능)를 반환합니다.

| 메서드 | 설명 |
|---|---|
| `s.addOperation(nameOrSignature, actionDict)` | 새 오퍼레이션 추가. 이름 대신 `'foo(x, y)'`처럼 인자를 받는 시그니처도 가능 |
| `s.addAttribute(name, actionDict)` | `addOperation`과 동일하지만 결과가 캐싱되는 Attribute를 추가 |
| `s.extendOperation(name, actionDict)` | 상위 Semantics의 오퍼레이션을 확장 (먼저 `g.extendSemantics()`로 상속 필요) |
| `s.extendAttribute(name, actionDict)` | 위와 동일하지만 Attribute용 |

오퍼레이션에 인자가 있으면, 액션 함수 안에서 `this.args.인자이름`으로 접근합니다. 예를 들어 `'prettyPrint(depth)'`라면 `this.args.depth`로 값을 꺼낼 수 있습니다.

## 시맨틱 액션은 파스 노드의 종류에 따라 다르게 작동합니다

파스 트리의 노드는 세 종류로 나뉩니다.

1. **규칙 적용(Rule application) / 논터미널(non-terminal) 노드**: 규칙을 호출한 부분
2. **터미널(Terminal) 노드**: 문자열/숫자 리터럴처럼 그 자체로 끝나는 부분
3. **반복(Iteration) 노드**: `*`, `+`, `?` 연산자와 관련된 부분

각 노드 종류에 따라 어떤 액션이 실행되는지 규칙이 있습니다.

- **논터미널 노드**: 먼저 규칙 이름과 같은 이름의 액션(예: `FullName`)을 찾습니다. 없으면 `_nonterminal` 액션을 찾습니다. 그것도 없고 자식이 딱 1개면, 그 자식에 대해 재귀적으로 값을 리턴합니다.
- **터미널 노드**: `_terminal` 액션을 사용합니다.
- **반복 노드**: `_iter` 액션을 사용합니다.

`_iter`와 `_nonterminal`은 인자 개수가 정해져 있지 않으므로 나머지 매개변수(`...children`) 문법으로 받는 게 일반적입니다. `_terminal`은 인자를 받지 않습니다.

```js
semantics.addOperation('eval', {
  _iter(...children) {
    return children.map(c => c.eval());
  },
  _terminal() {
    return this.sourceString;
  }
});
```

> ⚠️ 액션 함수의 매개변수 개수는 그 규칙이 만들어내는 값의 개수와 정확히 일치해야 합니다. 안 맞으면 에러가 발생합니다.

## 예시: 규칙 이름당 값이 몇 개 나오는지 이해하기

```
Name {
  FullName = name name
  name = (letter | "-" | ".")+
}
```

`FullName` 규칙의 본문은 `name name`, 즉 2개의 값을 만들어냅니다. 그래서 액션 함수도 인자를 2개 받아야 합니다.

```js
const actions = {
  FullName(firstName, lastName) { /* ... */ },
  name(parts) { /* ... */ }
};
```

## 파스 노드가 제공하는 정보

시맨틱 액션 안에서 각 노드(예: 위 예시의 `firstName`)는 다음과 같은 속성/메서드를 가지고 있습니다.

| 이름 | 설명 |
|---|---|
| `n.child(idx)` | idx번째 자식 노드 |
| `n.isTerminal()` | 터미널 노드인지 여부 |
| `n.isIteration()` | 반복 노드인지 여부 |
| `n.children` | 자식 노드 배열 |
| `n.ctorName` | 이 노드를 만든 규칙 이름 |
| `n.source` | 이 노드가 소비한 입력 구간(Interval 객체) |
| `n.sourceString` | 이 노드가 소비한 입력 문자열 그대로 |
| `n.numChildren` | 자식 노드 개수 |
| `n.isOptional()` | `?` 연산자로 생긴 노드(자식이 0개 또는 1개)인지 여부 |

그리고 Semantics 안에 등록된 모든 오퍼레이션/어트리뷰트는 노드에 메서드/프로퍼티 형태로 자동으로 붙습니다. 예를 들어 `prettyPrint` 오퍼레이션과 `freeVars` 어트리뷰트가 있다면, 모든 노드에 `node.prettyPrint()` 메서드와 `node.freeVars` 프로퍼티가 생깁니다.

## 내장 오퍼레이션: `asIteration`

`ListOf` 계열의 규칙을 다룰 때 유용한 내장 오퍼레이션입니다. 리스트 형태의 매칭 결과를 반복 노드처럼 다룰 수 있게 해줍니다.

```
G {
  Start = ListOf<letter, ",">
}
```

```js
s.addOperation('upper()', {
  Start(list) {
    return list.asIteration().children.map(c => c.upper());
  },
  letter(l) {
    return this.sourceString.toUpperCase();
  }
});
```

이제 `s(g.match('a, b, c')).upper()`를 호출하면 `['A', 'B', 'C']`가 반환됩니다. `asIteration()`으로 얻은 결과에 대해 `upper()`를 호출하면, 리스트의 각 원소마다 자동으로 `upper` 오퍼레이션이 적용(map)됩니다.

## 정리

- 문법과 동작은 완전히 분리되어 있고, `createSemantics()`로 연결합니다.
- `addOperation` / `addAttribute`로 동작을 등록하고, 액션 함수 이름은 규칙 이름과 일치시킵니다.
- 노드 종류(논터미널/터미널/반복)에 따라 특수 액션 이름(`_nonterminal`, `_terminal`, `_iter`)을 쓸 수 있습니다.
- `ListOf` 계열은 `asIteration()`으로 편하게 처리합니다.
