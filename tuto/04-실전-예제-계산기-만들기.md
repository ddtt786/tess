# 04. 실전 예제: 계산기 만들기

지금까지 배운 내용을 모두 합쳐서, `(2 + 3) * 4 - 1` 같은 수식을 실제로 계산하는 미니 계산기를 처음부터 끝까지 만들어봅니다.

## 1단계: 아주 간단한 예제로 감 잡기

본격적으로 들어가기 전에, 아주 짧은 예제로 흐름을 다시 확인해봅시다. "lol", "lmao", "loooool" 같은 문자열을 인식하는 문법입니다.

```js
const ohm = require('ohm-js');

const g = ohm.grammar(String.raw`
  Laugh {
    laugh = lol | "lmao"
    lol = "l" "o"+ "l"
  }
`);

console.log(g.match('lol').succeeded());       // true
console.log(g.match('lmao').failed());         // false (실패하지 않음, 즉 성공)
console.log(g.match('loooooool').succeeded()); // true
```

이제 진짜 계산기로 넘어갑니다.

## 2단계: 숫자만 인식하는 문법

가장 작은 단위부터 시작합니다. 숫자 하나 이상의 연속을 "number"라고 정의합니다.

```
Arithmetic {
  Exp = number
  number = digit+
}
```

- `digit`은 Ohm이 기본 제공하는 내장 규칙 (0~9)
- `digit+`는 숫자가 1개 이상 반복

## 3단계: 덧셈/뺄셈 추가하기

이제 `Exp`를 확장해서 덧셈과 뺄셈을 지원하게 만듭니다. 여기서 **좌재귀(left recursion)** 를 사용하는데, Ohm은 이걸 자연스럽게 지원합니다.

```
Arithmetic {
  Exp
    = AddExp

  AddExp
    = AddExp "+" PriExp  -- plus
    | AddExp "-" PriExp  -- minus
    | PriExp

  PriExp
    = "(" Exp ")"  -- paren
    | number

  number
    = digit+
}
```

포인트를 짚어보면:

- `AddExp = AddExp "+" PriExp` 처럼 자기 자신을 왼쪽에서 다시 참조하는 것이 좌재귀입니다. 이 덕분에 `1 + 2 + 3`이 `(1 + 2) + 3`처럼 왼쪽부터 계산되는 구조로 자연스럽게 파싱됩니다.
- `-- plus`, `-- minus`, `-- paren` 은 [02번 문서](./02-Ohm-문법-가이드.md)에서 배운 **인라인 규칙 선언**입니다. 각 분기가 `AddExp_plus`, `AddExp_minus`, `PriExp_paren`이라는 별도 규칙이 되어서, 나중에 시맨틱 액션을 각각 따로 작성할 수 있습니다.
- `PriExp`(우선순위가 가장 높은 표현식, Primary Expression)는 괄호로 감싼 식이거나 숫자입니다.

이 문법으로 매칭을 시도해봅시다.

```js
const g = ohm.grammar(String.raw`
  Arithmetic {
    Exp
      = AddExp

    AddExp
      = AddExp "+" PriExp  -- plus
      | AddExp "-" PriExp  -- minus
      | PriExp

    PriExp
      = "(" Exp ")"  -- paren
      | number

    number
      = digit+
  }
`);

console.log(g.match('2 + 3').succeeded());       // true
console.log(g.match('(2 + 3) - 1').succeeded());  // true
console.log(g.match('2 +').succeeded());          // false
```

`Exp`, `AddExp`, `PriExp`는 모두 대문자로 시작하는 **구문 규칙**이라서 공백을 자동으로 건너뜁니다. 그래서 `'2 + 3'`처럼 공백이 있어도, `'2+3'`처럼 없어도 둘 다 매칭됩니다.

## 4단계: 곱셈/나눗셈까지 추가하고 우선순위 지키기

곱셈과 나눗셈이 덧셈/뺄셈보다 먼저 계산되도록 하려면, "더 높은 우선순위 연산은 더 안쪽 규칙에 둔다"는 원칙을 씁니다.

```
Arithmetic {
  Exp
    = AddExp

  AddExp
    = AddExp "+" MulExp  -- plus
    | AddExp "-" MulExp  -- minus
    | MulExp

  MulExp
    = MulExp "*" PriExp  -- times
    | MulExp "/" PriExp  -- divide
    | PriExp

  PriExp
    = "(" Exp ")"  -- paren
    | number

  number
    = digit+
}
```

`AddExp`가 `MulExp`를 호출하고, `MulExp`가 `PriExp`를 호출하는 구조 덕분에 곱셈/나눗셈이 "더 강하게 묶이게" 됩니다. 이 원리는 [08번 문서](./08-실전-팁과-주의사항.md)의 "연산자 우선순위" 섹션에서 더 자세히 다룹니다.

## 5단계: 시맨틱 액션으로 실제 계산하기

이제 이 문법에 "eval"이라는 오퍼레이션을 추가해서, 매칭된 수식을 실제 숫자로 계산해봅시다.

```js
const semantics = g.createSemantics();

semantics.addOperation('eval', {
  Exp(e) {
    return e.eval();
  },
  AddExp(e) {
    return e.eval();
  },
  AddExp_plus(left, _op, right) {
    return left.eval() + right.eval();
  },
  AddExp_minus(left, _op, right) {
    return left.eval() - right.eval();
  },
  MulExp(e) {
    return e.eval();
  },
  MulExp_times(left, _op, right) {
    return left.eval() * right.eval();
  },
  MulExp_divide(left, _op, right) {
    return left.eval() / right.eval();
  },
  PriExp(e) {
    return e.eval();
  },
  PriExp_paren(_open, e, _close) {
    return e.eval();
  },
  number(_digits) {
    return parseInt(this.sourceString, 10);
  }
});
```

몇 가지 눈여겨볼 점:

- `AddExp_plus(left, _op, right)` 처럼, `"+"` 연산자 자체에 해당하는 인자는 값이 필요 없으니 관례적으로 `_op`처럼 밑줄로 이름 붙여서 "안 쓴다"는 걸 표시합니다.
- `number(_digits)` 액션에서는 `digit+`가 만든 값을 쓰는 대신, `this.sourceString`(이 노드가 소비한 원본 문자열)을 가져와 `parseInt`로 변환합니다. 이게 훨씬 간단합니다.
- `Exp(e)`, `AddExp(e)`, `MulExp(e)`, `PriExp(e)`처럼 "자식이 하나뿐이면 그대로 넘기는" 패턴이 반복되는데, 사실 이런 경우는 액션을 생략해도 Ohm이 자동으로 자식의 값을 그대로 반환해줍니다(자식이 정확히 1개일 때만). 하지만 명시적으로 적어두면 코드를 읽는 사람이 흐름을 이해하기 쉽습니다.

## 6단계: 실제로 계산해보기

```js
function calculate(input) {
  const matchResult = g.match(input);
  if (matchResult.failed()) {
    throw new Error(`계산할 수 없는 수식입니다: ${matchResult.message}`);
  }
  return semantics(matchResult).eval();
}

console.log(calculate('2 + 3 * 4'));       // 14
console.log(calculate('(2 + 3) * 4'));     // 20
console.log(calculate('10 - 2 - 3'));      // 5  (왼쪽부터 계산되므로 (10-2)-3)
console.log(calculate('100 / 5 / 2'));     // 10
```

`10 - 2 - 3`이 `5`가 나오는 이유는, 좌재귀 규칙 덕분에 `(10 - 2) - 3`으로 해석되기 때문입니다.

## 7단계: 잘못된 입력 처리하기

문법에 맞지 않는 입력을 넣으면 `match()`가 실패하고, `MatchResult`에 실패 정보가 담깁니다.

```js
const bad = g.match('2 + ');
console.log(bad.failed());        // true
console.log(bad.message);         // 어디서, 왜 실패했는지 설명하는 메시지
console.log(bad.shortMessage);    // 짧은 버전(입력 발췌 없이)
```

`message`는 최종 사용자에게 보여줘도 좋을 정도로 친절한 형태로 되어 있습니다. 자세한 내용은 [05-API-레퍼런스.md](./05-API-레퍼런스.md)의 MatchResult 섹션을 참고하세요.

## 전체 코드

```js
const ohm = require('ohm-js');

const g = ohm.grammar(String.raw`
  Arithmetic {
    Exp
      = AddExp

    AddExp
      = AddExp "+" MulExp  -- plus
      | AddExp "-" MulExp  -- minus
      | MulExp

    MulExp
      = MulExp "*" PriExp  -- times
      | MulExp "/" PriExp  -- divide
      | PriExp

    PriExp
      = "(" Exp ")"  -- paren
      | number

    number
      = digit+
  }
`);

const semantics = g.createSemantics();

semantics.addOperation('eval', {
  AddExp_plus(left, _op, right) { return left.eval() + right.eval(); },
  AddExp_minus(left, _op, right) { return left.eval() - right.eval(); },
  MulExp_times(left, _op, right) { return left.eval() * right.eval(); },
  MulExp_divide(left, _op, right) { return left.eval() / right.eval(); },
  PriExp_paren(_open, e, _close) { return e.eval(); },
  number(_digits) { return parseInt(this.sourceString, 10); }
});

function calculate(input) {
  const matchResult = g.match(input);
  if (matchResult.failed()) {
    throw new Error(`계산할 수 없는 수식입니다: ${matchResult.message}`);
  }
  return semantics(matchResult).eval();
}

console.log(calculate('2 + 3 * 4')); // 14
```

## 정리

문법과 시맨틱을 분리해서 만드는 전형적인 흐름은 이렇습니다.

1. 문법을 우선순위/구조에 맞게 계층적으로 설계한다 (예: Exp → AddExp → MulExp → PriExp)
2. 각 분기에 `-- caseName`으로 이름을 붙여서 시맨틱 액션을 쉽게 매핑할 수 있게 한다
3. `createSemantics()` + `addOperation()`으로 각 규칙에 대응하는 계산 로직을 작성한다
4. `match()`로 검사하고, 실패하면 `message`로 원인을 알려준다
